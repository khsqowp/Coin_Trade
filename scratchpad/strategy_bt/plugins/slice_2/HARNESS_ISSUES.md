# Harness issues found by slice 2 (common/ NOT modified; worked around)

1. **Timestamps lost in evaluation.** `common/protocol.py::evaluate` builds train/test frames with `reset_index(drop=True)`, so `signals()` receives a RangeIndex during evaluation while `check_no_lookahead` receives the DatetimeIndex. Any calendar/session strategy (day-of-week, 08:00 UTC sessions, daily VWAP resets, daily-ATR via security) cannot work off `df.index`. Workaround: `plugins/slice_2/s2_lib.py::timestamps()` recovers the timestamps by exact open/close fingerprint matching against the cached parquet files (deterministic; raises if no match).
2. **Random-entry null ignores plugin-specific exit logic that is not column based.** Null entries copy `long_exit/short_exit/stop/tp/max_hold` columns from the strategy. For session strategies this is handled by using a constant `PARAMS["max_hold"]` (null then holds one session); for the Monday strategy the null keeps the Monday exit signals so null hold lengths are 1-7 days, not 1 day.
3. **No same-open reversal.** In `engine.simulate` an exit fill executes with `continue`, so an entry from the same signal bar cannot fill; reversal systems (Parabolic SAR, Supertrend flip) are flat one extra bar. Not patched.
4. **`PARAMS` are static across timeframes**, so a bar-count based parameter (session length in bars for `max_hold`) cannot differ by timeframe; session plugins therefore run on one timeframe.
5. Stop `atr_stop` is converted via `/px` (fill price incl. slippage) and `stop_pct` is relative to the fill price, so signal-bar-based R distances are approximate when the open gaps from the signal close.
