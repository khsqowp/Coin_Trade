# Harness issues found by slice_1 (common/ NOT modified; worked around in plugins)

1. **Same-bar reversal is impossible / always delayed one extra bar.** In `common/engine.py::simulate`, when a position is closed by a signal exit at bar `i` open the loop does `continue`, so a new entry is never evaluated on bar `i`; the entry check at bar `i+1` reads `entry[i]`, not `entry[i-1]`. An always-in stop-and-reverse strategy whose entry and opposite-exit signals fire on bar `t` therefore exits at open `t+1` but only re-enters at open `t+2` (and only if the entry signal is still true on bar `t+1`). Workaround in plugins using reversals: `_sticky(...)` repeats the reversal entry signal on bar `t+1` (unless the new position's own exit has fired). Effect: reversal entries execute one bar later than in the archived strategy (a slight, usually adverse, delay at 1h/4h; negligible at 1d relative to trade duration).
2. **TRAIN/TEST slices are passed to `plugin.signals` with the DatetimeIndex dropped.** `common/protocol.py::evaluate` does `v.iloc[:k].reset_index(drop=True)`, so `df.index` is a RangeIndex and time-of-day / day-of-week logic is impossible from the frame alone (the pre-run `check_no_lookahead` call passes the full parquet with its DatetimeIndex, so it does not reveal this). Workaround in the two calendar/resample-dependent plugins (08 UTC sessions x6, weekend momentum, ft_volatility_system): recover timestamps by exact OHLCV matching of the frame against the cached parquet in `../bb_stoch_stc/data` (or `$STRATEGY_BT_DATA_DIR`). Metadata lookup only. If the data dir is moved the plugin raises instead of silently mis-timing.
3. **The random-entry null reuses the strategy's management columns bar-by-bar** (`stop_pct`, `atr_stop`, `tp_pct`, `max_hold`, exit signals taken from the observed signal frame at the random entry bar). Plugins that only set stop/target/max_hold on their own signal bars (NaN elsewhere) get a null with NO stop/target/time exit, which is not matched to the observed trades (for time-boxed session strategies a null trade could stay open to the end of the sample). Workaround: set max_hold on every bar; fill off-signal stop/tp bars with the causal expanding median of past signal-bar distances (a full-sample median would itself be lookahead; caught by check_no_lookahead). Residual: null exit-signal columns are still the strategy's own exit signals evaluated at unrelated bars.
4. **No way to hold between an entry and a session end without an explicit exit signal other than `max_hold`.** Used `max_hold` (close of bar entry+max_hold) for the 12-hour session strategies; works but any gap in the cached bars would shift the exit time.
5. (Informational) Candidate counting in `run.py` loads every `.py` under `--plugins-dir` repeatedly via `_load`, executing module-level code each time (plugins must be import-cheap; helper modules are not importable by sibling plugins, so shared code is inlined per plugin).
6. (Informational) `compliance.audit` treats a spec key as "present" even when its value is null, so null fields (e.g. `stop_loss: null`) must be listed in `IMPLEMENTED_FIELDS` to avoid a WARN even though there is nothing to implement.
