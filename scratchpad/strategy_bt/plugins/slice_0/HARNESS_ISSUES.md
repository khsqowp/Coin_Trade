# Harness issues found by slice 0 (common/ NOT modified; worked around)

1. **Timestamps are dropped before plugins see data.** `common.protocol.evaluate` does `reset_index(drop=True)` on train/test frames, so `df.index` is a RangeIndex inside real runs (but is still a DatetimeIndex in `check_no_lookahead`, which uses the raw parquet). Any clock-based strategy (session allocation, NYSE-close) cannot know the hour. Workaround: `plugins/slice_0/s0_timeutil.py` recovers the true timestamps by exact OHLC prefix-matching the frame against the cached parquet files. Test: recovered signals == signals on the dated frame.
2. **Reversals are delayed/lost.** After any exit the engine `continue`s, so a same-bar flip is impossible; a re-entry needs the entry signal to be True on the *exit bar* (i.e. one bar after the flip signal). One-bar cross pulses are therefore lost for stop-and-reverse systems. Workaround in btc-ema-5-30: pulse-extended entry signals (documented in DEVIATIONS). Affects any strategy that reverses.
3. **One-point grids can never PASS.** Plateau is `NA` for a one-point grid and `decide` requires `ROBUST`. Specs with no free parameters would be un-passable by construction; slice-0 session plugins therefore add a cut-hour axis (documented as a deviation).
4. **Symbol universe is hard-coded to 5 majors regardless of the spec's instrument** (BTC-only / ETH-only specs are pooled with SOL/XRP/BNB, and "3 of 5 symbols positive" is judged across them). Verdicts for BTC-only specs are therefore not a test of the spec's own instrument.
5. **Time-limit semantics:** `max_hold=H` exits at the close of bar entry+H (H+1 bars held). Plugins must use H=bars-1; not a bug but easy to misuse.
6. **Secondary symbols** are run on the full history (train+test) with frozen params, so `secondary_return` is not out-of-sample.
7. Entry/exit are evaluated at the next bar open only; stops/TPs use one fixed distance per trade fixed from the signal bar (cannot express trailing, time-decaying ROI, or entry-price-relative levels).
