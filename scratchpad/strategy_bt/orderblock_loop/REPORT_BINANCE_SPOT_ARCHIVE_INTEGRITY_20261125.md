# Binance Spot 공개 아카이브 무결성·유니버스 재점검 — 2026-11-25

## 결론

공식 Binance Spot 아카이브는 과거 캔들의 조달 경로로는 유효하지만, 다운로드 이름·체크섬만으로 가격 정확성이나 과거 종목 전체성을 증명하지 않는다. 월간 파일과 일간/API 간 불일치 사례 및 과거 상장 심볼 매니페스트 미확정이 남아 있어, 이 자료로 고정 코인 전략 데이터 게이트를 열지 않았다.

## 확인한 공식 자료

- Binance의 공식 `binance-public-data` 안내는 Spot `klines`가 `/api/v3/klines`에서 비롯되고, 전체 캔들 간격과 일/월 단위 아카이브 및 체크섬을 제공한다고 설명한다. 이 안내는 다운로드 형식과 제공 경로를 설명하지만 과거 데이터 정확성, 심볼별 완전성, 월간 파일과 일간 파일의 동일성을 보증하지 않는다. [공식 저장소 README](https://github.com/binance/binance-public-data/)
- 공식 저장소 이슈 [#475](https://github.com/binance/binance-public-data/issues/475)는 2026-06-30에 열린 상태로 게시돼 있고, 2026-11-16 댓글에서도 미해결이라고 보고한다. 보고자는 10개 심볼과 1m·5m·15m·1h 간격에서 2020-12-21 및 2021-09-29 월간 파일의 캔들 값이 일간 아카이브와 현재 API/UI Kline 값에 다르다고 기술했다. 최초 비교 398행은 모두 일간 파일/API와 일치했다고 보고됐고, 추가 검토에서는 과거 수정분이 월간 파일에 반영되지 않은 사례와 거래소 중단 시간대에 월간 파일이 0거래 캔들을 넣은 사례가 제시됐다. 이는 공식 유지관리자의 판정이 아니라 공개 이슈 작성자의 재현 주장이다. 해당 날짜·심볼 외로 오류가 일반화되는지는 확인하지 않았다.
- 공식 저장소 이슈 [#479](https://github.com/binance/binance-public-data/issues/479)는 과거 특정 시점의 전체 Spot 심볼, 상폐·이름 변경·마이그레이션된 심볼을 포함하는 공식 역사 매니페스트가 있는지 질문한다. 열람 시점까지 이 범위를 확정하는 유지관리자 답변은 보이지 않았다. 기존 이슈 [#238](https://github.com/binance/binance-public-data/issues/238)의 유지관리자 댓글은 심볼이 거래소에서 제거되면 해당 심볼의 캔들 생성이 멈추고, 이름 변경된 심볼의 자료는 새 이름 아래 있을 수 있다고 설명한다. 과거 기호와 새 기호의 자산 연속성을 완전히 대사하는 규칙은 제시하지 않았다.

## 전략 연구 게이트에 미치는 영향

- 현재 프로젝트의 고정 G는 가격 파일 존재만으로 열리지 않는다. 고정 기간·코호트, PIT 상장 상태, 가격 연속성, 무결성, 상폐/이름변경 처리 및 자료 이용권을 함께 입증해야 한다.
- 기존 Binance Spot 1h 목록에서 BTCUSDT의 2018·2022 월별 객체 이름과 체크섬 파일 존재는 확인됐지만, 실제 바이트/체크섬 비교·내부 행·공통 30종목·PIT 유니버스·연속성은 아직 미확인이다. 공개 이슈 #475는 특히 월간 파일을 선택해 단독으로 사용하는 접근의 추가 정확성 위험을 만든다.
- Binance Spot은 USDⓈ-M 무기한 선물과 다른 시장이다. Spot으로 별도 실험을 설계할 수는 있지만, 기존 선물 R11/R12 결과와 합치거나 선물 전략의 2018 가격 대체치로 간주하지 않는다. 현물 전략은 별도 사전등록·비용 모델·trial count가 필요하다.
- 한국·미국 주식 자료 경로의 기존 미해결 문제에는 새 변화가 없으며, 해당 시장 실험을 시작할 새 데이터 증거도 이번 조사에서 얻지 않았다.

## 이번 단계 범위

공식 문서와 공개 이슈 페이지를 읽고, Angolin이 무인증·무과금이라고 문서화한 공개 `/v1/exchange_pairs?exchange=binance&interval=1h` 카탈로그에 브라우저로 GET 요청 1회를 했다. 이는 유료 인증 API 호출이 아니며, 가격 행이나 캔들 파일을 받은 것이 아니다. 응답의 일부 `first_close_ts` 값은 ADA/USDT `2018-04-17T05:00:00Z`, XRP/USDT `2018-05-04T09:00:00Z`, VET/USDT `2018-07-25T05:00:00Z`였다. 이는 제공자가 기록한 최초 1시간봉 시각이지 거래소가 공식 확인한 상장일이 아니다. 반환된 `first_close_ts`/`last_close_ts` 정의상 실제 자료 범위의 끝점이며, 중간 연속성이나 모든 과거 심볼의 완전성을 보장하지 않는다. 추가 query parameter `base=BTC&quote=USDT`를 붙인 read-only 조회도 했지만 응답은 필터링되지 않아 전체 목록을 되풀이했다. 다운로드, 계정 생성, 유료/API key 호출, 가격행 열람, 사전등록 수정, 장부 읽기/쓰기, 백테스트 또는 테스트 실행은 하지 않았다. 기존 파일이나 공유 연구 장부는 수정하지 않았다.

## 공개 카탈로그의 실제 한계

- 카탈로그 설명은 결과를 “해당 시장/간격에 캔들이 하나 이상 있는 모든 거래쌍”으로 정의하고, 첫·마지막 close 시각은 실제 자료 범위의 끝점일 뿐 gap-free 범위가 아니라고 명시한다. 따라서 해당 응답은 후보 종목을 찾는 메타데이터 자료다.
- 카탈로그의 `exchange_pairs`는 `base`/`quote` 필터를 지원하지 않는다. 한 번의 응답은 대량 전체 목록이며, 이를 2018년 당시 거래 가능한 전체 USDT 코호트로 사용할 수 없다.
- 시점별 listing periods를 제공한다고 문서화된 `exchange_universe` endpoint와 periods 다운로드는 인증 키 및 요금제 권한이 필요하다. 이번 작업에서는 키 발급·계정 생성·유료 접근을 하지 않았다.
- 세 개의 2018년 `first_close_ts`는 일부 자료가 기간 중 존재했음을 보이는 유용한 단서지만, 온전한 2018년 전체 기간, 동일 2022 코호트, gap-free 가격, 상장/상폐 이벤트의 시점 정확성 또는 자료 이용권을 증명하지 않는다.

## 2026-11-25 공개 메타데이터 집계

공개 1h 카탈로그를 다시 한 번 조회해 응답 전체를 브라우저 안에서 집계했다. 응답은 3,690개 거래쌍이며, quote가 USDT인 쌍은 731개였다. 이 중 `first_close_ts`가 2019-01-01 UTC 이전인 쌍은 23개다. 이 23개 중 `last_close_ts`가 2023-01-01 UTC 이후인 쌍은 20개였다. 이는 각 쌍이 그 두 시각 사이에 거래됐다는 뜻이 아니라, 최초·최종 관측값의 범위가 두 기준점을 걸친다는 뜻이다.

20개 끝점 겹침 목록: ADA/USDT, BCH/USDT, BNB/USDT, BTC/USDT, EOS/USDT, ETC/USDT, ETH/USDT, ICX/USDT, IOTA/USDT, LTC/USDT, NEO/USDT, NULS/USDT, ONT/USDT, QTUM/USDT, TRX/USDT, TUSD/USDT, USDC/USDT, VET/USDT, XLM/USDT, XRP/USDT. 2018-01-01 UTC 이전 또는 당일에 첫 관측이 있는 쌍은 6개였다.

이 숫자는 API 응답 시점의 메타데이터 집계이며, 응답의 바이트/체크섬을 별도 보존한 데이터셋 감사가 아니다. 첫·마지막 관측 사이의 공백, 각 쌍의 2018/2022 전체 연속성, 해당 시점의 실제 상장 상태, 무기한 선물 시장과의 동일성, 2018년 당시 전체 상장 코호트, 2017년부터 생존·상폐된 자산의 완전성은 증명하지 않는다. 그러므로 20개는 가격 데이터 수집 후보 목록일 뿐, 고정 코호트나 통과한 데이터 게이트가 아니다. 캔들/가격 행은 내려받거나 열지 않았다.

## 다음 판정 단계

1. 사용 가능한 공식/허가된 경로에서 고정 날짜 기준의 과거 Spot 심볼 목록을 만들 수 있는지 출처·기간·이름변경 이벤트 단위로 입증한다.
2. 고정 코호트가 확정된 뒤에만 2018·2022 파일별 체크섬 검증, 월간/일간/API가 중복되는 구간의 원천 대조, 타임스탬프 중복·누락·0거래 바 검사를 계획한다.
3. 데이터 원천이 통과하기 전에는 전략 가설, 파라미터, 성공 기준을 결과에 맞춰 바꾸지 않고 새 라운드·trial 기록을 만들지 않는다.
