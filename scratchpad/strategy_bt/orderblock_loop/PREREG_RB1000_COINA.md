## 2. 다중검정 분모 (Bonferroni)
- `N = 실행 직전 TRAIN_TRIALS.csv 데이터 행수 + 429 + 1000`.
  - 429: EXPLORE500 채점 설정(장부 미반영). 1000: 4개 레인 전체 설정 수(다른 레인 동시 실행 가능분을 보수적으로 전부 가산).
- 작성 시점 확인값: 장부 3,189행 → N = 4,618 (실행 직전 재집계 값으로 대체하고 보고서에 실제 값을 적는다).
- 유의수준: 설정별 거래 단위 단측 정규근사 p < 0.05 / N. 군집 보정 p도 같은 임계를 쓴다.
- 실행 시 장부 잠금(`.cointrade_train_trials.lock`, `.ob_attrition_train_trials.lock`)을 잡고 행수를 센 뒤, 300행을 `fcntl.flock` 아래 단일 `os.write`로만 추가한다. 추가 전 행수가 바뀌었으면 아무 행도 쓰지 않고 중단한다. 잠금을 다른 레인이 잡고 있으면 중단하고 보고한다.

## 4. 신호 정의 (모든 값은 바 i 종가 시점에 알려진 정보만 사용)
공통 규칙: 신호 `dirs[i]`는 바 i 종가에 결정되고, 진입은 바 i+1 시가(next-bar-open). z-score는 `[i-120, i-1]` 구간(현재 바 제외) 평균·표준편차 대비다.

- **데이터 유효성 규칙(신호 정의 불변)**: 0 이하 OI는 무효 데이터로 결측 처리(신호 없음). TRAIN 바가 0개인 종목(ENAUSDT, POLUSDT, TONUSDT)은 거래하지 않는다(유니버스 35는 그대로이며 결과 분모 `n_symbols=35`도 그대로). 중복 메트릭 타임스탬프는 마지막 행을 쓴다.
- **파생 시점 규칙**: 메트릭 스냅샷(5분)은 "종가 이전 마지막 스냅샷"만 쓴다. funding 정산은 정산 시각이 바 i 종가보다 앞설 때만 알려진 것으로 본다. 1분 데이터(프리미엄, 테이커)는 바 i 내부 분 봉의 합·평균만 쓴다(바 i 종가에 모두 확정).
- **D1**: 기준 funding `r`(마지막 정산값 또는 최근 3회 평균). `r ≥ thr` → 숏(군중 롱 역배팅), `r ≤ -thr` → 롱. trigger=event면 이번 바에서 새 정산이 알려진 바만 신호.
- **D2**: 비율 로그값의 z. `z ≥ thr` → 숏, `z ≤ -thr` → 롱.
- **D3**: OI 로그 변화 z(w바). `z ≥ thr`일 때 가격 w바 수익률이 양수면 롱(continuation) 또는 숏(fade), 음수면 반대.
- **D4**: 프리미엄 평균(w바 이동평균)의 z. fade: `z ≥ thr` 숏, `z ≤ -thr` 롱. follow는 반대.
- **D5**: 테이커 불균형 `2·(매수 거래량 합/전체 거래량 합)−1`(w바 가중)의 z. follow: `z ≥ thr` 롱. fade는 반대.
- **D6**: w바 OI 수익률 ≤ −x 이고 w바 전 종가 대비 하락폭 ≥ 1.5·ATR → 롱만(청산 플러시 반등 프록시).
- **D7**: 직전 바가 ATR/종가 비율의 200바 분위 ≤ p 압축이고, OI 12바 수익률 > 0이며, 종가가 직전 20바 고가 돌파(롱) 또는 저가 이탈(숏).

## 5. 실행 규칙 (고정)
- 체결: next-bar-open. 손절 = 2·ATR(14), 목표 = reward_r × 위험폭, 최대 보유 horizon_bars. 출구 판정은 `crypto.simulate_trade`를 그대로 쓴다(봉 내 손절·목표 우선순위 포함).
- 비용: 편도 수수료 4bp + 슬리피지 2bp = 6bp/편도. funding은 `adverse_only` 정책(`crypto.simulate_trade` 기본 처리). 
- 중첩: **심볼별 1포지션**. 보유 중 발생한 신호는 건너뛴다(`skipped_overlap`). 여러 심볼이 같은 봉에 신호를 내도 심볼별로 독립 처리한다(자본 한도 없음).
- 워밍업: 바 인덱스 500 미만은 신호 무시(기존 harness 규칙).
- 포트폴리오 일간 수익: 심볼 합 / 35(기존 `score_config` 관례). 연환산 365일.
- 룩어헤드 금지: 위 §4 규칙 + 절단 테스트(입력을 k번째 바 이전으로 자른 결과와 전체 결과가 k 이전 신호에서 일치해야 함) + 합성 테스트(다음 바 시가 진입, 정산 시각 지연 반영, 1분 봉 경계 귀속) 통과가 실행 전제다.
- 다른 레인 장부 행이 실행 중 추가되면 실행 직전 행수 불일치로 장부 쓰기 없이 중단한다.

## 6. 합격 규칙
### 6.1 코어 게이트 (기존 G 핵심, `metrics.core_gate(market="crypto")`, 완화 없음)
- 거래 수 ≥ 100 (코드 기준), 누적 수익 > 0, PF ≥ 1.30, 기대값 ≥ +15bp, Wilson 95% 하한 > 손익분기 승률, MDD < 누적수익/2, 연환산 Sharpe ≥ 1.0, 지급능력 유지.
- Bonferroni: 거래 단위 단측 정규근사 p < 0.05 / N (§2).

### 6.2 보강 검정 5종 (모두 필수, 하나라도 실패하면 "후보 아님")
1. **1봉 지연**: 모든 신호를 1바 늦게 실행(진입 = 신호 바 + 2바 시가). 기대값 ≥ 15bp 이고 PF ≥ 1.30.
2. **비용 2배**: 편도 수수료 8bp + 슬리피지 4bp. 기대값 ≥ 15bp 이고 PF ≥ 1.30.
3. **진입일 군집 보정 p**: 거래를 진입 UTC 일자로 묶어 군집 평균 손익을 만든 뒤 단측 정규근사 p < 0.05 / N.
4. **연도별**: 거래 ≥ 20인 연도 중 기대값 양수 비율 ≥ 2/3. 약세 연도 2022에 거래 ≥ 20이면 2022 기대값 ≥ 0. 판정 가능한 연도가 없으면 실패.
5. **상위 3종목 제외**: 심볼별 누적 손익 상위 3개를 제외한 나머지의 기대값 ≥ 15bp 이고 PF ≥ 1.30.

### 6.3 최종 라벨
- 6.1 전부 + 6.2 전부 통과: **통과 후보(TRAIN_ONLY_NOT_G)**. 이 라벨은 G 승격·OOS 실행을 뜻하지 않는다.
- 그 외: **후보 아님**, 실패 항목을 장부에 적는다.
- 배치 결과 통과 후보가 0개면 0개라고 쓴다.
