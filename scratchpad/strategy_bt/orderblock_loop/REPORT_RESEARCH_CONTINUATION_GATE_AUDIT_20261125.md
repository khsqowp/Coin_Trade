## 범위와 실행하지 않은 항목

이번 재개 감사에서 읽은 것은 연구 보고서·사전등록 요약, 데이터 파일 경로와 Parquet footer 통계, 공개 공식 자료다. 추가로 `r19._assert_no_ledger_writer()` 통과 후 장부를 스트리밍해 데이터 행 수와 R33–R37 다섯 개 행의 ID·설정 지문·TRAIN 요약치만 읽었다. 현재 장부는 4,194행이며 다섯 라운드가 각 1개 `completed` 행으로 저장돼 있다. 가격 행, 나머지 장부 세부값, 비밀값, API 계정은 확인하지 않았다. 새 preregistration, 백테스트, 다운로드, API 호출, 가격 데이터 취득, 공유 장부 쓰기, 실거래는 하지 않았다. `ps`는 이 환경에서 `operation not permitted`로 실패했으므로 해당 명령으로 전체 프로세스 종료 상태를 단정하지 않는다.

사용자가 전달한 R11 정정 감사는 별도 사실로 보존한다. 0.25R EV 구간은 `−36.00~−19.25bp`로 수정됐고, 48행 표·신뢰구간 재계산과 단위 테스트 43/43, no-index diff check 및 trailing-whitespace 점검이 통과했다고 보고됐다. 이 감사에서는 R11 테스트를 다시 실행하지 않았다. R12는 preregistration과 runner만 있으며 hash 고정·테스트·실행·장부 기록은 없다고 전달받았다.

## R38 현재 파일 상태 — 정적 확인

현재 체크아웃에는 R38 상세 사전등록, runner, 테스트 파일이 모두 있다. 본 보고서 작성 시점의 SHA-256은 사전등록 `46eb2c2d429f52161558f51fa6db3dd6aefbace5a14ff66ce3b3ac59407206c9`, runner `7686152d978e3a6da33df037023fc151389dba063f0cb72a1fbbe8471cee2180`이다. 테스트 파일은 존재하지만 이번 감사에서 실행하지 않았다. R38은 문서 자체가 R14/R37 TRAIN을 본 뒤 만든 적응형 탐색이며, 파생 입력·비용 모델도 R14와 공유한다고 명시한다. 따라서 그 결과가 이후 기록되더라도 독립 증거 또는 G 통과로 셀 수 없다.

정적 코드에서는 첫 접촉 직전 세 완료 1h봉만 확인하고, 필터 실패 시 부모 zone을 소진하며, 다음 봉 진입·R14 비용/funding simulator를 재사용하도록 작성된 것을 확인했다. 이후 재검사에서 `r19._assert_no_ledger_writer()`가 통과했고, 공유 장부는 4,194 data rows·기대 스키마·R38 중복 없음으로 대사됐다. 고정 split SHA도 사전등록 값과 일치했다. 이는 확인 시점의 결과이며 향후 writer 부재를 보증하지 않는다.

R38 preregistration의 footer 게이트를 Parquet 메타데이터만으로 확인했다. 1h·4h 고정 universe 35개 파일은 모두 단일 row group이었다. footer의 `complete` 통계가 전체 row group에서 true인 파일은 1h 17/35, 4h 7/35였고, cutoff 이전에 끝나는 row group은 두 간격 모두 0개였다. 따라서 사전등록의 footer-only cutoff-safe 공통 30심볼 조건을 통과하지 못한다. R38 runner와 가격행은 열지 않았다.

독립 정적 검토도 현 R38 runner를 실행하지 말라고 판정했다. footer helper는 사전등록 문구의 “모든 row group”과 달리 조건을 만족하는 row group 하나만 찾으면 심볼을 통과시킬 수 있고, 다중 row group 경계의 실제 footer 통합 테스트가 없다. 잠금은 이 runner의 잠금 파일을 쓰는 실행끼리만 배제하므로 오래된 무잠금 writer와의 배타성은 구조적으로 증명되지 않았다. 이번 자료는 모든 파일이 단일 row group이고 footer 게이트도 30개에 못 미치므로 결과는 같지만, 코드·테스트 파일은 소유권이 불명확해 수정하지 않았다. 테스트·가격행·백테스트·장부 쓰기는 하지 않았다.
