## 4. 실행 차단과 규칙

- TRAIN은 여러 종목·설정의 대량 연산이다. macOS에서 `nice -n 10 true`가 `nice: setpriority: Operation not permitted`로 실패했다. 자원 규칙상 요구되는 낮은 우선순위를 적용할 수 없어 실제 탐색을 시작하지 않았다.
- `/Users/user/CODE/trading_data/cache/.heavy.lock`은 존재하지 않았고 외부 cache 쓰기 권한이 없다. 지시된 로컬 fallback 위치에서 PID 69251 lock을 만들었지만 우선순위 설정이 거부되어 작업은 시작되지 않았다. signal 0으로 PID 부재를 확인하고 이 실행이 만든 고아 lock만 제거했다.
- 프로세스 목록 조회는 `ps`에서 `Operation not permitted`, `pgrep`에서 `Cannot get process list`로 차단됐다. 다른 프로세스를 종료하지 않았다.
- OS의 RLIMIT_AS 설정도 `current limit exceeds maximum limit` 오류로 설정되지 않았다. 코드는 단일 심볼 shard와 최대 RSS 3GiB 검사로 대체했으나, 이 경로는 백테스트가 실제 시작되지 않아 검증되지 않았다.
- cutoff 이후 OHLC 행은 탐색에 입력되지 않았다. TEST는 실행하지 않았다.
