# R6 이후 라운드 설계 계획

## 결론

지금 바로 데이터 결함 없이 실행 가능한 신규 전략 격자는 **0개**다. R6은 새 백테스트가 아니라 선결자료·기존 R4 완료 확인으로 시작한다. 결손 자료나 품질 기준을 임의로 보완하지 않고, 새 가설은 각 실행 전에 PREREG.md addendum에 등록한다.

## 3. 신규 TRAIN 가설 후보와 trial 계획

아래는 **제안 단계**이며 아직 사전등록·실행된 격자가 아니다. 모두 고정 TRAIN만 쓴다. 격자 수는 장부에 더해질 계획 trial 수다. 시간은 문서의 R2/R5 계획·실측을 바탕으로 한 용량 추정이며 실측값이 아니다. 입력 품질/최소 표본 게이트를 못 넘으면 실행하지 않고 0회로 기록한다.

| 순위/후보 | 새 가설(기존 실패 재탕 제외) | 근거와 데이터 게이트 | 사전등록 격자 | 누적 trial 증가 | 예상 실행시간 |
|---|---|---|---:|---:|---:|
| 1 / 코인 R6-A | 오더블록 진입 후 변동성 군집별 위험 제한: ATR 백분위 구간에 따라 동일한 OB 신호의 고정 손절 폭/보유시간 조합이 달라지는지 평가 | R4 결과를 보기 전에 정의를 고정한다. 기존 OB 3정의·주기·방향·대기기한·목표 격자와 중복하지 않는다. funding 유효성·최소 30심볼·cutoff·완성봉·fingerprint 및 sentinel 검증을 전부 통과한 경우만. | 2 ATR 구간 × 2 stop buffer × 2 최대 보유 = **8** | **+8**; 실행 전 실제 장부 N 확인 후 고정 | 실행기/자료 처리량 실측 전 **확인 안 됨**. 72설정 R4와 같은 시간으로 외삽하지 않는다. |
| 2 / 코인 R6-B | OB 최초 재방문이 아니라 재방문 뒤 확인봉의 종가 위치(구간 상단/하단 대비)를 진입 품질 신호로 쓰는 단일 정의 | R4의 기존 재방문 정의 및 설정과 독립된 정의인지 사전 코드리뷰한다. funding/표본 게이트는 R6-A와 동일. 둘 다 동시에 돌리지 않는다. | 2 확인 임계값 × 2 청산 보유 = **4** | **+4** | **확인 안 됨**; 파일 로드와 단일 설정 벤치마크 후 산정 |
| 3 / US R6-C | 단일 종목 추세 돌파 대신 월간 단면 상대강도 상위군의 다음 거래일 매수·정기 교체 | 현재 보유 US 패널의 OHLC가 선택 구간에서 무결하고 전처리 fingerprint가 고정되더라도 PIT/상폐 누락이 해결되지 않으면 **시장 전체 가설로 실행 불가**. PIT 확보 전에는 진행 대기. | lookback 3 × 보유군 2 × 교체주기 2 = **12** | 실행 승인 시 **+12** | R5 KR 계획치는 US로 전이 불가. 벤치마크 후 추정; 현재 **확인 안 됨** |
| 4 / KR R6-D | 단면 상대강도 상위군의 다음 거래일 매수·월간 교체 | OHLC 1틱 처리 addendum과 고정 hash, 515개 통과 집합의 사전 고정 및 정산가격/PIT 결손 해결이 모두 선행해야 한다. 1틱 처리만으로 상폐 편향이 사라지지 않는다. | lookback 3 × 보유군 2 × 교체주기 2 = **12** | 실행 승인 시 **+12** | R5의 KR 계획 추정은 다른 규칙·표본에 적용 불가. 벤치마크 후 추정; 현재 **확인 안 됨** |

현재 적격 실행 가능 수는 **0**이다. R6-A/B도 현재 잠긴 R4와 혼합 실행하지 않으며, R4 결과를 보고 파라미터를 고치지 않는다. 신규 코인 가설은 결과 확인 전 별도 addendum으로 고정한다. US/KR은 데이터 게이트가 닫힌 동안 실행·성과 주장으로 진행하지 않는다.

## 4. 우선순위와 실행 순서

1. **현재 R4 코인 72설정**: 사용자 제공 운영상태는 공유 .heavy.lock 보유, 약 20시간 소요 중이다. 상태를 독립 조회하지 않았고 이 값은 사용자 입력이다. 해당 실행 완료/중단 및 lock 해제 확인 전까지 다른 heavy 작업을 시작하지 않는다. 프로세스를 종료하지 않는다.
2. 완료 후 R4 산출물·단일 code hash·data fingerprint·미판정 사유·실제 시간을 대조한다. R4의 성공/실패는 미리 단정하지 않는다.
3. 코인 funding coverage 및 unscorable 집계가 사전등록 문턱을 만족하는지 검토한다. 불충족이면 코인 새 가설 실행도 대기하고 자료 결손으로 보고한다.
4. 다음 heavy 슬롯에서 R6-A **8설정만** 단독 실행한다. 완료/기록 확인 후 R6-B addendum과 4설정을 별도 실행한다. 각 배치 전에 .heavy.lock, 실행 프로세스 부재, 메모리/디스크/우선순위 규칙을 다시 확인한다. lock 경로는 저장소 외부의 기존 경로를 그대로 사용하고 우회하지 않는다.
5. US/KR은 PIT·상폐자료 조달 결정을 먼저 해결한다. KR은 1틱 규칙을 addendum으로 선등록하고 데이터 입력 검증까지 끝낸다. 둘 중 하나라도 막히면 해당 시장의 R6 후보는 0회, G/TEST 제출 0개로 기록한다.
6. TEST 구간은 동결 후보만 한 번 사용한다. 현재 자료 제약이 해소되기 전에는 동결·TEST 열람을 하지 않는다. G 기준, 비용, 표본 문턱, 다중검정 보정을 낮추지 않는다.

## 5. 12라운드 상한 소진 계획

현재 자료에 명시된 진행단계는 R5 이후이며, 남은 계획 슬롯은 **R6~R12 총 7라운드**다. 라운드는 탐색 성공 여부와 무관하게 소비한다. 자료 대기가 길어져도 라운드 수를 늘리지 않는다.

| 라운드 | 할당 | 최대 신규 trial | 조건/중단 기준 |
|---|---|---:|---|
| R6 | 코인 R6-A, R6-B | 12 | R4 잠금 해제 및 funding·표본 게이트 통과 뒤 순차 실행. 실패·미판정도 전부 장부에 포함. |
| R7 | 사전등록된 코인 독립 정의 1개 | 최대 8 | R6 결과를 보기 전 별도 addendum을 먼저 등록. 결과 본 뒤 같은 정의 재튜닝 금지. funding 결손이면 0. |
| R8 | US R6-C | 12 | PIT/상폐가격 데이터·권리·고정 universe hash가 확인된 경우에만. |
| R9 | KR R6-D | 12 | 공식 정산/상폐자료, OHLC 규칙 addendum 및 fingerprint 확인 뒤에만. |
| R10 | 코인 독립 새 정의 1개 또는 남은 코인 데이터 결함 해결 | 최대 8 | R7과 겹치지 않는 메커니즘을 사전등록. 데이터 해결에만 쓰이면 trial 0. |
| R11 | 시장별 사전등록 독립 가설 1개 | 최대 12 | 해당 시장 자료 게이트를 통과한 시장만 실행; 미통과 시장은 0. |
| R12 | 남은 가설 1개 또는 종료 감사 | 최대 8 | 마지막 라운드. G 미달/자료 미해결이면 못 찾음으로 종료. 새 라운드 연장 금지. |

이 상한안의 신규 가설 최대치는 **72 trial**(12+8+12+12+8+12+8)이며, 실제 누적 분모는 실행 직전 장부의 전체 행 수에 실패·미판정 시도를 포함해 더한다. 현재 실제 장부 행 수는 재집계하지 않았으므로 N은 **확인 안 됨**이다. 설정 수를 다 채우는 것이 목표가 아니다. 각 후보는 독립성, 표본 수, 자료 무결성, 사전등록 기준을 통과해야 하며, 최대 12라운드에서도 기준을 통과하지 못하면 전략 미발견으로 종료한다.
