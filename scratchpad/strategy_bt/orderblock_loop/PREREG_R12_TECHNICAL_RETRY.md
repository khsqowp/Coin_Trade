# R12 기술 오류 수정 재실행 사전등록

작성: 2026-11-24, 두 번째 데이터 실행 전

## 이유와 경계

첫 R12 실행은 6개 설정 모두 `RecursionError`로 장부에 기록됐다. 원인은 zone 필터가 R4 zone 생성 함수를 monkeypatch한 뒤, 자기 자신을 다시 호출한 구현 결함이다. 해당 6행은 실패 시도로 보존하며 삭제하거나 성공으로 재분류하지 않는다. 첫 실행은 지표를 만들지 못했으므로 전략 성과 결과로 해석하지 않는다.

이번 실행은 같은 R12 라운드의 기술 오류 복구다. zone 생성기의 원본 함수를 명시적으로 전달하도록 고친다. 전략 가설, 입력 데이터, cutoff, 유니버스, 설정 6개, 신호·진입·청산·비용, 평가 지표, 선별 및 G 합격 기준은 기존 `PREREG_R12_BTC_DAILY_ALIGNMENT.md`와 완전히 동일하다. 새 파라미터나 전략 선택은 추가하지 않는다.

## 고정 재실행

- 설정은 displacement/BOS-origin/volume-displacement 각각 롱·숏, 4시간봉, 총 6개다.
- 동일 cutoff: 봉 마감 `2023-11-06T16:00:00Z` 이하인 TRAIN만 사용한다. 최종 TEST 및 2026-06-01 이후 자료는 열지 않는다.
- 첫 실행의 오류 시도 6개를 포함한 현재 다중검정 분모는 1,660이다. 이번 6개 복구 시도를 포함한 종료 분모는 1,666이며 Bonferroni 단측 경계는 `0.05/1666 = 0.0000300120`이다. 실패행은 분모에서 제외하지 않는다.
- 기존 6개 실패행은 그대로 둔다. 이번 6개 결과는 별도 trial ID와 새 사전등록 해시로 append한다.
- 결과가 나오더라도 TRAIN 선별만 의미한다. 역사 데이터 자격, OOS/최종 TEST, 레드팀 강건성 및 전체 G 조건을 충족하지 않으면 검증 후보로 부르지 않는다.

## 실행 전 검증

1. R12 회귀 테스트에서 zone builder가 원본 생성기를 한 번만 호출하는지, RecursionError가 재현되지 않는지 검사한다.
2. BTC 완료 일봉 구성·EMA 초기화·미래 불변성·strict-prior regime 테스트 7개를 통과시킨다.
3. 사전등록 SHA를 러너에 고정하고, 실행 직전 R12 writer 부재와 장부의 현재 행 수를 확인한다.
4. 여유 공간이 40 GiB 이상인지 확인한다. 실패하면 실데이터 실행하지 않는다.

## 결과 처리

각 복구 설정은 성공·실패를 모두 장부에 남긴다. 다시 기술 오류가 나면 추가 재시도하지 않고 라운드 상한 내 구현 실패로 보고한다. 성과가 기준 미달이면 원인을 보고하되, 이 사전등록에서 기준·격자·데이터를 바꾸어 재탐색하지 않는다.
