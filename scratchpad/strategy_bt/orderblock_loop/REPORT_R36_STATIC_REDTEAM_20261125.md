이는 테스트 픽스처의 동작을 확인한 결과다. 실제 Binance 자료의 cutoff·연속성·심볼 범위, 실험 장부 상태, R36 시장 성과 또는 최종 G를 입증하지 않는다.

## 남은 선행 결함·증거 공백

- **사전검사 실패가 장부에 남지 않을 수 있다.** `_run_locked()`의 writer 부재·행수·중복·사전등록 hash·여유 공간·split manifest 검사가 내부 `try`보다 먼저 실행된다. 이 단계에서 실패하면 사전등록의 “실패도 시도로 기록” 규칙에 따른 실패 행이 남지 않는다. `_acquire_locks()`도 `run()`의 `try/finally`보다 먼저 실행되며 잠금 경로가 없으면 예외가 장부 기록 없이 반환된다. 현재 잠금 경로는 존재하나 이 실패 경로의 동작은 테스트되지 않았다.
- **다음 봉 시가 체결은 코드 경로만 확인했다.** R14 `_make_setup()`은 `entry = next_bar.open`과 `confirmation_index + 1`을 사용하고 simulator는 setup 가격이 해당 봉 시가와 일치하는지 검사한다. 그러나 R36 통합 테스트는 저장된 trade의 `entry_index`와 `entry_price`가 확인봉 다음 봉의 시각·시가인지 직접 단언하지 않는다.
- **미래 변조 테스트 범위가 제한적이다.** 현재 테스트는 확인봉 이후 봉을 바꾸고 wick 분류 카운터를 비교한다. 전체 신호 ID, 다음 시가 진입, 실제 결과 분리 또는 인과 시점 경계 전체를 독립 oracle과 비교하지 않는다.
- **불확실 append 경로가 테스트되지 않았다.** `os.write` 부분 기록, `fsync` 실패, `close` 실패를 모의해 `AppendUncertainError` 발생과 재시도 금지를 확인하는 테스트가 없다. 현재 성공 append 픽스처만 있다.
- **게이트 순서가 동작 테스트되지 않았다.** 행수·중복·writer·hash·split·disk 게이트가 실패할 때 `iter_train_bars`가 호출되지 않는다는 mock 검증이 없다. 사전등록 hash와 코드 hash를 고정한 뒤 파일이 변하면 중단하는 경로도 테스트하지 않았다.
- **독립 Red-team 검토는 수행됐지만, 실행 승인은 없다.** 감사에서 식별된 공백의 코드 수정·재검토는 아직 확인되지 않았다. 본 보고서는 검토 결과를 기록하며 실행 승인으로 간주되지 않는다.
- **동시성 상태 미확인.** `ps` 권한 오류 때문에 프로세스 종료를 확인하지 못했다. 파일 쓰기 descriptor가 관찰되지 않은 사실은 계산 중이거나 이후 장부를 다시 열 프로세스가 없다는 증거가 아니다.
