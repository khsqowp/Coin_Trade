# R7 코인 오더블록 사전등록·실행·시각 감사 보고

## 결론

R7 BTC 상승 레짐 필터 오더블록 전략의 TRAIN 실행 1건이 장부에 있다. 기대값 +6.15bp, PF 1.023, 연환산 Sharpe 0.096으로 개발 성과 기준에 미달한다. M2 목표 선도달률은 기록되지 않아 G 통과 후보가 아니다. 기존 실행의 시각 정합성은 아직 확정할 수 없다.

## 사전등록 설정

- 가설: BTC 4시간 종가가 SMA(150) 위이고 SMA(150)가 24개 4시간 봉 전보다 높을 때, 알트코인 4시간 롱 `bos_origin` 오더블록 첫 재방문만 거래한다.
- 설정 1개: 48봉 재방문 기한, ATR(14)×0.10 손절 여유, 2R 목표, 48봉 최대 보유, `adverse_only`, TRAIN 전용.
- R3/R4 독립성 비교는 실행하지 않았다. R7을 독립 후보로 세지 않는다.
- 기존 PREREG의 공통 G 기준 및 더 엄격한 R7 기대값 문턱 ≥30bp를 유지한다. 이번 TRAIN 결과는 OOS/G 판정이 아니다.

## 시각 인과성 감사

기존 커밋은 BTC 레짐과 알트 신호 조회 모두 캔들 시작 시각을 키로 사용했다. 코드상 BOS 신호는 해당 알트 봉의 종가가 확정되어야 생성되고, 데이터 입력은 4시간봉 UTC 격자를 공유한다. 이 격자가 실제 입력 전 구간에서 유지됐다면 같은 시작 시각의 BTC 봉 종가와 알트 신호 봉 종가는 동시에 알려지므로, 확인한 코드 경로에서 미래 BTC 봉을 미리 참조했다는 증거는 없다. 다만 이번 감사는 대용량 시계열 원본을 다시 열어 실제 전체 바 정렬을 검증하지 않았고, 별도 실행 로그도 없다. 따라서 **코드에서 직접적인 룩어헤드 증거는 발견하지 못했지만, 과거 실행의 입력 정합성·완전한 재현까지 인증한 것은 아니다.**

수정 코드 `search_crypto_r7.py`는 BTC 상태를 봉 마감/사용 가능 시각(`open_time + 4h`)에 기록하고, 알트 신호도 해당 봉 마감 시각에서 조회한다. 합성 회귀 테스트는 봉 마감 전에 새 BTC 레짐을 사용할 수 없고, 마감 시각부터 사용할 수 있음을 검증한다. 이는 시간 의미를 명시하는 개선이며 과거 실데이터 행을 다시 계산한 결과는 아니다. 기존 R7 행은 TRAIN 탐색 기록으로 보존하며, 독립 재현·G 통과·후속 검증 없이 검증 후보로 승격하지 않는다.

## 검증 상태와 다음 작업

- R7 개별 합성 테스트: 6개 통과.
- 전체 `unittest`: 227개 통과, 0 실패.
- 전체 시도 장부: 1,531행 (CSV 헤더 제외). R7 실데이터 행은 1개.
- OOS/TEST 및 2026-06-01 이후 데이터: 열지 않음.
- R3/R4 중복·상관, 비용 2배, 1봉 지연, 약세장, 무작위 귀무, 평탄도, Bonferroni/Reality Check/SPA/Deflated Sharpe: R7에서 실행하지 않음.
- 이전 보고의 “실데이터 실행과 TEST 열람을 하지 않았다” 중 실데이터 실행 부분은 장부와 모순된다. 이 보고서가 정정한다. TEST 미열람은 장부의 TRAIN cutoff와 코드 범위로 확인했다.
- 원격 GitHub 확인: 네트워크 DNS 오류로 `git ls-remote` 실패. 원격 최신 상태 및 push 여부는 확인되지 않았다.
