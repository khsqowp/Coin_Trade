# 공시 기반 "누가 샀다/팔았다" 연구 계획 (기관·내부자·국회의원)

작성 2026-11-22. 상태: 계획 + 비회원 데이터 일부 확보. 실행(백테스트)은 아직 안 함.
이 문서는 "사라"는 신호가 아니라 **공개된 거래 사실**을 가설의 입력으로 쓰는 연구 계획이다.
`AGENTS.md` 규칙(사전등록, 시도 장부, 다중검정 보정, 2026-06-01 이후 동결)을 그대로 따른다.

## 0. 핵심 원칙 (이걸 어기면 결과 무효)
1. **시점은 공시일**. 거래일이 아니다. 공시 전에는 시장이 모르는 정보다. 거래일로 백테스트하면 미래 정보를 쓰는 것이고 수익이 가짜로 나온다.
   - 진입 가능 시점 = 공시가 공개된 시각 이후 첫 봉 시가(체결은 다음 봉 시가). 공시 시각을 모르면 그날 종가 이후로 보수적으로 처리.
2. 공시 지연이 길수록 효과가 사라진다. 지연 구간별(0-2일 / 3-10일 / 11-45일)로 쪼개서 보고한다.
3. 같은 종목에 여러 명이 겹치면 한 번만 센다(클러스터는 하나의 이벤트).
4. 금액이 구간으로만 공개되는 자료(국회의원)는 구간 중앙값이 아니라 "구간 하한"으로 보수적으로 쓰고, 거래 건수 기준 가설을 우선한다.
5. 생존편향: 상폐 종목이 가격 데이터에 없으면 한계로 결과표 맨 위에 적는다.

## 2. 이미 확보한 것 (이번 세션)
- 위치: `~/CODE/trading_data/external/disclosures/house/` 에 `2014FD.zip ~ 2026FD.zip` (13개, 합계 약 1.1MB), sha256은 `MANIFEST_sha256.csv`.
- 내용: 하원 재무공시 **색인**(XML+TXT). 의원 이름, 선거구, 공시 종류, 공시일, 문서 번호(DocID)만 있다. **실제 거래 내역(종목·매수/매도·금액 구간)은 PDF 안에 있어서 아직 없다.**
- 거래 보고서(PTR, 종류 P) 건수: 2015 728, 2016 765, 2017 801, 2018 830, 2019 683, 2020 733, 2021 680, 2022 624, 2023 460, 2024 451, 2025 515, 2026 477. 합계 약 7,700건 (2014는 색인 1건뿐이라 사실상 비어 있음).
- PDF 주소 형식: `https://disclosures-clerk.house.gov/public_disc/ptr-pdfs/<연도>/<DocID>.pdf` (한 건 HEAD 응답 200 확인).
- 확인 안 됨: PDF가 텍스트 PDF인지 스캔본인지(오래된 건 스캔 이미지일 가능성), 건당 용량(대략 100KB 가정 -> 합계 약 1GB 추정).

## 3. 단계 (각 단계는 별도 승인 후 실행)
### 단계 1. 데이터 확보 (돈 안 듦)
- 1-A SEC 일괄 파일(Form 4, 13F)을 받는다. **준비물 1이 있어야 시작.** 용량 수 GB 이하(분기 zip 수십 MB x 약 80분기), 월 단위로 받아 parquet(zstd)로 바꾼 뒤 원본 zip은 지운다.
- 1-B 하원 PTR PDF 본문을 받는다. 초당 1건 이하로 천천히(약 7,700건, 약 2~3시간), 이어받기 가능하게 DocID 단위로 저장. 먼저 20건 샘플로 텍스트 추출 가능 여부 확인. 텍스트가 안 나오는 스캔본은 건수만 기록하고 건너뜀(OCR은 별도 승인).
- 1-C OpenDART: 임원·주요주주 소유보고와 대량보유 보고를 종목 코드별로 받는다. 일 20,000건 한도, 2015년부터. **준비물 2 필요.**
- 1-D KRX 투자자별 순매수(기관/외국인/개인)와 공매도 잔고. **준비물 3 필요.** pykrx 방식은 로그인 필요로 막혀 있음, 공식 계정으로만.
- 모든 파일은 행 수·sha256 매니페스트로 검증. 저장소 안에 데이터를 넣지 않는다.

### 단계 2. 이벤트 표 만들기
- 공통 스키마: `source, filer_type(insider/institution/politician), filer_id, symbol, side(buy/sell), trade_date, disclose_date, amount_low, amount_high, shares, price`.
- 종목 코드 매핑(티커/CUSIP/종목코드)을 별도 표로 만들고 매핑 실패율을 보고한다(실패를 조용히 버리지 않는다).
- 가격 데이터와 연결 시 공시일 이후 구간만 쓰는 인과성 테스트를 먼저 통과시킨다.

### 단계 3. 가설 사전등록 (PREREG.md 먼저, 결과 보기 전)
후보 가설 (시도 횟수는 모두 장부에 센다):
- H1 미국 임원 **여러 명 동시 매수** 클러스터(30일 안에 3명 이상) 후 20/60거래일 초과수익.
- H2 미국 임원 **대규모 단독 매수**(금액 상위 구간)와 매도 대비 매수 비율.
- H3 한국 임원·주요주주 매수 공시 후 20/60거래일 초과수익.
- H4 한국 5% 대량보유 신규 취득(국민연금·외국계 구분) 후 초과수익.
- H5 미국 하원 의원 거래: 공시 후 20/60일 초과수익, 지연 구간별. 상원은 준비물 4가 있을 때만.
- H6 13F 분기 신규 편입 종목(여러 기관 동시 편입). 45일 지연이라 기대치 낮음, 마지막 순위.
- 기준 수익률: 같은 시기 같은 시장(S&P500 / KOSPI)과 같은 규모·업종 무작위 종목. 무작위 이벤트 날짜 귀무(최소 1000회) 대비 95퍼센타일.
- 통과 기준(요약, 결과 전 고정): 이벤트 수 충분(미국 300건 이상, 한국 100건 이상), 비용 후 평균 초과수익 > 0, 승률의 95% 구간 하한이 50% 위, 다중검정 보정 후 통과, 비용 2배/1일 지연 통과, 2022 약세장 손실 아님, 한 해에 수익 50% 이상 집중되지 않음. 세부 숫자는 단계 3에서 PREREG에 고정.

### 단계 4. 검증과 보고
- 구현자와 다른 에이전트가 독립 재구현. 룩어헤드·집중도·비용 스트레스·평탄도 점검.
- 쉬운 한국어, 건수·승률·평균 초과수익(비용 후)·손익비·최대 낙폭·보정 후 p값을 표로.
- 결과가 없으면 "없다"고 쓴다. 이 계열은 지금까지 검증된 엣지가 아니라 **새 후보 가설**일 뿐이다.

## 4. 기대치 (정직하게)
- 임원 클러스터 매수는 학계에서 약한 초과수익 보고가 있다(우리 데이터로 재현된다는 보장은 없음).
- 의원 거래는 연구마다 결과가 갈리고, 45일 지연 때문에 공시 시점 기준으로는 대부분 사라진다는 쪽이 우세하다.
- 13F는 분기말 스냅샷 + 45일 지연이라 단기 신호로는 약하다.
- 한국은 신뢰할 수 있는 가격·종목코드 이력은 있으나 상폐 종목 누락 여부 확인이 필요하다.

## 5. 자원·비용 규칙
- 이번 계획 전체 비용 0원(전부 무료 공개 자료). AWS 사용 안 함.
- 다운로드는 한 번에 하나, 초당 1건 이하, `nice -n 10`. 시작 전 스왑 3GB 미만 확인(현재 3.5GB 사용 중이라 대용량 변환은 Mac 정리 후).
- 키·이메일은 환경변수로만 받고 코드·문서·커밋에 쓰지 않는다.

## 6. 준비물 (사용자가 발급·결정할 것) — 마지막에 한꺼번에
1. **SEC 접속용 연락처 결정**: SEC는 요청 헤더(User-Agent)에 "이름 이메일" 형식의 연락처를 요구한다. 어떤 이름/이메일을 헤더에 쓸지 정해서 알려주거나, 환경변수 `SEC_USER_AGENT="이름 이메일"`로 직접 설정. (내가 임의로 네 이메일을 외부에 보내지 않는다.) 계정 가입은 필요 없음.
2. **OpenDART API 키**: https://opendart.fss.or.kr 회원가입 → 인증키 신청(즉시 발급, 무료). 환경변수 `OPENDART_API_KEY`. 채팅에 붙여넣지 말 것.
3. **KRX 데이터 포털 계정**: https://data.krx.co.kr 회원가입(무료). 로그인 정보는 환경변수 `KRX_ID`, `KRX_PW`로만(채팅 금지). 자동 로그인이 막혀 있으면 직접 CSV 내보내기로 대체할 수 있음(투자자별 순매수 기간별 다운로드).
4. (선택) 상원: https://efdsearch.senate.gov 에서 약관 동의 후 검색. 자동화는 약관 동의 단계 때문에 우회하지 않는다. 필요하면 직접 CSV 내보내기 후 `~/CODE/trading_data/external/disclosures/senate/`에 넣어주기.
5. (선택) 한국은행 ECOS 키, Alpaca 키는 이 계획과 무관(기존 P2 목록 항목).
6. 결정 필요: PDF 스캔본 OCR을 할지(기본: 안 함), 시작 시점(기본: 키 받은 뒤 단계 1부터).

## 7. 결정 기록 (2026-11-22, 사용자 답변)
- 스왑 무시하고 진행. SEC 연락처(준비물 1)와 KRX 계정(준비물 3)은 불필요로 결정 -> 미국 내부자 Form 4/13F와 한국 순매수는 이번 범위에서 제외(필요 시 다시 연다).

- PDF 처리: Microsoft `markitdown`으로 Markdown 변환, 글자가 안 나오는 스캔 PDF만 tesseract OCR(회전 보정 포함). 스크립트 `data_sources/disclosures/fetch_house_ptr.py` (재개 가능, 초당 1건).
- 산출물: `~/CODE/trading_data/external/disclosures/house/{ptr_pdf,ptr_md,ptr_manifest.csv}`. 변환 결과는 줄바꿈이 없는 한 덩어리 텍스트라 거래 행 파싱은 단계 2에서 별도로 한다. OCR 결과는 오인식이 있어 파싱 실패율을 보고한다.
