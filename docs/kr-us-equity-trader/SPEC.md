# 국장·미장 주식·ETF 자율매매 — 요구사항 명세

버전: 0.1 (2026-11-14)
상태: 목표와 1차 검증 방식 확정. 위험 한도·데이터·브로커·런타임 등은 미확정. 실거래 승인 문서가 아니다.

## 1. 목적

한국 및 미국 주식·ETF를 대상으로 전략을 연구·검증하고, 최종적으로 검증된 전략과 제한 조건 안에서 자율적으로 매매하는 에이전트 시스템을 만든다. 목표 연 수익률은 약 20%다. 이는 연구 목표이며 수익 보장, 예상 수익 또는 실거래 승인으로 해석하지 않는다.

## 2. 범위와 경계

- 대상 시장: 한국 주식·ETF와 미국 주식·ETF.
- 제외: 코인, 선물, 옵션, 외환 및 기타 파생상품.
- 목적 제품: 자율매매. 기존 코인 차트 분석·알림 제품과 별도 시스템·별도 명세로 관리한다.
- 현재 단계: 백테스트만 수행한다. 백테스트를 브로커 모의주문 또는 실거래로 부르지 않는다.
- 향후 모의주문·실거래 전환은 별도 단계와 승인 게이트를 통과해야 한다. 본 문서만으로 주문 API, 계좌 접근, 자금 운용을 허가하지 않는다.
- 에이전트 프레임워크(Hermes, OpenClaw, Codex 기반 자체 구성 등), 페르소나/역할 분담, 스킬·플러그인 구성은 조사·선정 대상이며 아직 미정이다.

## 3. 성과 목표와 위험

- 목표: 연 환산 수익률 20% 수준을 전략 탐색 목표로 둔다. 성과는 수수료·세금·슬리피지 가정을 명시한 순수익과 총수익을 함께 보고한다. 구체적인 연환산 산식과 세금 처리 기준은 데이터·계좌 범위를 정할 때 확정한다.
- 성과 보장 금지: 목표를 만족하지 못하면 낮은 결과를 그대로 보고한다. 과거 성과로 미래 수익을 약속하지 않는다.
- 최대 허용 낙폭: **미정**. 사용자 확정 전까지 자동매매 준비 완료 판정을 내리지 않고, 실거래 전환을 진행하지 않는다.
- 포지션 크기, 종목별/시장별 한도, 현금 비중, 손실 정지, 거래 빈도, 재조정 규칙은 백테스트 전에 사전 등록한다. 수치를 정하지 않은 항목은 임의 기본값으로 채우지 않고 미확정으로 기록한다.
- 성과는 수익률뿐 아니라 최대 낙폭, 변동성, 회복 기간, 위험조정 수익, 거래비용 민감도, 시장별·연도별 편중을 함께 평가한다.

## 4. 백테스트 요구사항

- 전략 가설·파라미터·유니버스·기간·비용 가정을 시험 전에 기록하고 각 시도를 누적한다.
- 개발·검증·봉인 구간을 분리한다. 봉인 구간은 최종 판정 외에는 열람하거나 튜닝에 사용하지 않는다.
- 당시 실제로 투자 가능했던 종목 유니버스, 상장폐지·합병·티커 변경, 분할·배당 등 기업행동을 처리해 생존편향과 미래정보 유입을 줄인다.
- 체결 시점과 가격, 거래소별 거래시간, 휴장일, 호가/유동성 한계와 비용을 명시한다. 누락한 비용은 결과에 분명히 표시한다.
- 단순 매수보유 및 적절한 시장지수 기준선과 비교한다. 한국과 미국 성과를 합산해 한 시장의 부진을 가리지 않고 시장별로 따로 보고한다.
- 핵심 결과는 재현 가능한 데이터 스냅샷, 코드/전략 버전, 거래 내역, 시험 횟수, 신뢰구간 또는 표본 한계를 포함한다.
- 단일 최고 수익 조합 선택을 피하고 워크포워드·다중시험 편향·비용 민감도·극단 구간을 확인한다.

## 5. 에이전트와 스킬·플러그인 산출물

전략 검증이 끝난 후 자율매매 런타임을 선정하고 아래를 별도 산출한다.

- 역할/페르소나: 시장 분석, 포트폴리오 구성, 위험 승인, 주문 실행, 감사·모니터링의 권한과 책임.
- 스킬·플러그인 목록: 각 항목의 용도, 데이터 접근, 실행 권한, 출처·라이선스, 유지보수 상태, 검증 결과.
- 주문 실행기는 위험 게이트와 별도 분리한다. 분석 모델만으로 한도나 주문 정책을 변경할 수 없게 한다.
- 각 도구는 최소 권한을 쓰고, 자격 증명을 코드·로그·보고서에 남기지 않는다. 주문·취소·보유 현황은 사후 감사 가능한 기록으로 남긴다.
- 외부 GitHub 저장소를 설치·실행하기 전에 라이선스와 코드 경로를 점검한다. README의 성능 주장은 실증 근거로 취급하지 않는다.

## 6. 단계

| 단계 | 목표 | 완료 기준 |
|---|---|---|
| E0 | 투자정책·위험한도 확정 | 최대 낙폭과 포지션/시장 한도 등 사전 등록 |
| E1 | 데이터·유니버스 확정 | 한국/미국 각각의 재현 가능한 데이터 및 기업행동 감사 |
| E2 | 전략 가설 백테스트 | 기준선·비용·편향을 포함한 재현 보고서 |
| E3 | 검증·봉인 평가 | 사전 등록한 기준을 봉인 표본에서 통과하거나 실패로 판정 |
| E4 | 에이전트·스킬 설계 | 역할, 권한, 스킬·플러그인, 감사/위험 경계 검토 |
| E5 | 모의 주문 시험 | 별도 승인 후 실행; 백테스트 결과와 구분된 전향 검증 |
| E6 | 실거래 검토 | 사용자 명시 승인, 운영·보안·위험 점검 통과 후 별도 결정 |

현재는 E0/E1 준비와 가정·한계를 명시한 탐색적 백테스트를 할 수 있다. 최대 허용 낙폭과 기타 사전등록 조건이 확정되기 전에는 최종 봉인 평가(E3), 자율 주문 준비 완료 판정, 모의주문·실거래 전환을 승인된 것으로 간주하지 않는다.

## 7. 미확정 결정 목록

- 최대 허용 낙폭 및 낙폭 발생 시 자동 정지/재개 규칙.
- 거래 유니버스: 시가총액·거래대금·최소 가격·ETF 유형·레버리지/인버스 ETF 포함 여부.
- 초기 자본, 종목/포지션 한도, 현금 유지, 리밸런싱 주기.
- 벤치마크, 목표수익률 산식, 세금과 거래비용 가정.
- 한국·미국 데이터 제공자와 과거 데이터 범위.
- 브로커, 계좌/API 권한, 프레임워크 및 에이전트 런타임.
- E3/E5/E6 통과를 위한 구체적 통계 기준과 전향 시험 기간.

미확정 사항은 사용자가 결정하기 전까지 명세의 미정 상태로 유지한다.
