# Trading research pipeline (test env)
Flow: data store -> Researcher(deepseek-flash, + strategy library) -> Engineer(gpt-5.4-mini, tool calling) -> deterministic ablation -> Auditor(claude-haiku-5-5) -> Risk Engine gate -> [candidate export] -> Telegram notice.
Run (all via locked-down containers, image tp-pipeline:local; build: docker build -t tp-pipeline:local .):
  ./run.sh data data-fetch            # Binance public OHLCV -> data/ (parquet + meta.sqlite w/ sha256)
  ./run.sh kis kis-fetch              # KIS PAPER daily candles (005930, 000660)
  ./run.sh data data-verify | data-list | data-get --symbol BTC/USDT --tf 1d
  python3 driver.py pipeline --run-id my-run
  python3 driver.py demo --fixtures B1_shift_neg,B5_weekly_bfill
  python3 driver.py bench --models claude-haiku-5-5,deepseek-flash,gpt-5.4-mini --reps 3
  ./run.sh agent budget               # LLM spend ledger (follow-up task: \$1.5 allowance on top of the \$0.14975 baseline, auto-stop at 80% = \$1.20 new spend)
  unit tests: docker run --rm --network none --entrypoint python -v \$PWD/src:/app/src:ro -v \$PWD/tests:/app/tests:ro tp-pipeline:local -m pytest /app/tests
Secrets: secrets/llm.env (4 LLM keys) -> agent role only; secrets/kis.env -> kis role only. TOSS/Binance keys are never copied. Code written by LLMs runs only in the sandbox role (no network, no env).

### Regime agent (`src/tp/regime.py`, `./run.sh agent regime-run --market crypto|kr|us|all`)
Inputs: as-of price features (trend, momentum acceleration, volatility, volume change), BTC flow (ETH lead/lag and correlation, ETH/BTC ratio as dominance PROXY), summarized news/features, and the two separate liquidation sources. Output: fixed JSON schema (label, confidence, event_risk, rationale with evidence ids that must exist in the input, strategy_weights over a fixed family list, risk_multiplier in [0,1]). Cheap model (deepseek-flash) + Auditor-class consistency check (claude-haiku-5-5). Every judgement is appended to `runs/regime_log.sqlite` (append-only triggers + hash chain: `./run.sh agent regime-verify`).
**NO BACKTEST USE**: the model may remember what happened after a historical date, so news/regime judgements are never used in historical backtests. They are evaluated forward only (regime_log vs later realized prices). The strategy pool is backtested without the agent.
Prompt-injection controls: no tools in the call, news wrapped in `<<<UNTRUSTED_NEWS_DATA ... UNTRUSTED_NEWS_DATA>>>` (our delimiters are defanged inside the text), schema + id validation, risk can only be reduced, no code path from the output to orders/config/network. Test: `./run.sh agent regime-injection-test`.

### Strategy pool (`strategy_pool/`, deterministic, `./run.sh sandbox pool-evaluate`)
Interface: `RULES`, `generate_signals(df, disabled=frozenset())`, `META`, `PROTECTIVE`, `RULE_KINDS`, optional `NEEDS_BTC`, `verifiable()`.
coin: trend_mtf (15m/1h/4h-style consensus + ATR trail), mean_reversion, breakout_squeeze, momentum_accel, chart_patterns (pivot confirmation delay K=5; S/R breakout+retest, double bottom, ascending triangle, bull flag; no images), btc_regime_alt (ETH with BTC regime filter), liq_cluster (UNVERIFIABLE). stocks: trend_sma200, tsmom (+`pool.rotation_picks`), lowvol_quality. KR: kr_surge_chase (UNVERIFIABLE: needs 1-minute data, simulator `tp.krsurge`, paper only, no order code).
`UNVERIFIABLE` strategies get `backtest.unverifiable` and the gate blocks them (`UNVERIFIABLE_STRATEGY`). Allocator (`tp.allocator`): regime weights -> exposure, clamped by the Risk Engine profile (`tp.risk.PROFILES`: crypto_fast / kr_equity / us_equity, values identical to RiskConfig defaults; frozen).
Pipeline run for one pool strategy: `python3 driver.py pool-run --strategy coin_trend_mtf --symbol BTC/USDT --tf 1h` (Researcher describes -> Engineer writes tests -> sandbox backtest -> ablation -> Auditor -> Risk gate; never exports).
Costs used for coin strategies: 0.10% fee + 0.05% slippage per side (the gate's minimum is lower; not relaxed).

### Protective rules (E)
A rule listed in `PROTECTIVE` is not blocked as dead because history never triggers it. It must FIRE on deterministic synthetic stress (`tp.stress`: gap crash -12/-25%, 10 consecutive -3% bars, halt-like zero-volume gap then -20%), injected at bars where the strategy is long: plain test (rule off lets the strategy stay long) or isolated test (all other exits off). No fire anywhere => dead => BLOCK. Non-protective rules keep the old policy. Tests: `tests/test_protective.py` (reproduces the `hard_catastrophe_stop` case of run fu-crypto-003-h2).

### Liquidation concentration (same format from two sources, `tp.liqmap`, `./run.sh offline liq-maps`)
(2) Binance proxy = ESTIMATE from public OI history + long/short ratio + klines with assumed leverage mix (5/10/20/50/100x), proportional closes, sweep by bar range, mmr 0.5%; positions older than the OI window are invisible; real exchange-wide leverage distribution is unknown. (3) Hyperliquid = MEASURED SAMPLE of positions of addresses seen trading >= $25k (no official full account list exists, we do not scrape indexers) -> coverage vs exchange OI is printed. Both are labelled unverified; `coin_liq_cluster` stays UNVERIFIABLE until >= 90 days of history.

### Survival arena (F) -- virtual capital, smoke only
`src/tp/arena.py`, `./run.sh sandbox arena-smoke`. 2-4 virtual accounts (100,000 virtual USDT), inference cost deducted each epoch (real ledger cost or base x multiplier), bankruptcy line (20%), retire-worst/clone-best, every order through RiskEngine.check_order (agents cannot change the frozen config). Metrics per epoch: pressure, distance to bankruptcy, average position fraction, position changes -> `runs/arena/arena.sqlite`.

## Round 2: operations, scheduler, research (appended)
**Correction to the sentence at the top of this file**: a regime-agent scheduler now exists (`tp-sched`, below), ON by default, with a hard daily cap.

### Services (`./svc.sh start|stop|status|logs <news|kis|deriv|hl|watch|sched|all>`)
tp-news (RSS/GDELT/F&G/funding/OI, Yahoo US daily, kline updater every 30 min for the forward tracker), tp-kiscol (KIS paper minute bars), tp-deriv (Binance public liquidation/OI), tp-hl (Hyperliquid read-only), tp-watch (watchdog + daily summary, no LLM, 512 MB), tp-sched (regime scheduler, 512 MB / 0.5 CPU, read-only rootfs, no ports, only DEEPSEEK/ANTHROPIC keys via `secrets/sched.env` 600).
All: `--restart unless-stopped`, log rotation, 127.0.0.1 only (none listens). State survives restarts (heartbeats, sched slot memory in `runs/sched_status.json`, watch state in `runs/watch_state.json`).

### Scheduler (tp-sched)
Crypto hourly at :02, KR 23:30 + 06:40 UTC, US 12:30 + 21:30 UTC (3 h catch-up after a restart; each slot runs once). Crypto carry gate: a new LLM call only if >= 6 h since the last, the deterministic regime changed, |4h move| > 2.5%, or >= 3 new crypto news and >= 2 h; otherwise the previous judgement is re-logged as source `carry` at cost 0. Daily cap `TP_DAILY_CAP` (default $0.30 per UTC day, scheduler spend only): once reached, remaining LLM slots are skipped (and the day is reported in the summary). Round budget $3 total, hard stop at 80%.
STOP: `./svc.sh stop sched`, or without touching Docker `touch runs/SCHED_DISABLED` (checked every loop; remove the file to resume). Judgements are append-only in `runs/regime_log.sqlite` (hash chain: `./run.sh agent regime-verify`).

### Watchdog / daily summary (tp-watch, no LLM)
Every 60 s: heartbeat ages of all collectors, KIS in-session freshness, deriv/hl stream silence, scheduler heartbeat, disk free < 20% (warn) / < 10% (critical), budget >= 60%. Telegram on new issue, re-alert after 6 h, message on recovery. Daily summary at 23:00 UTC (collection counts, anomalies, budget, latest regime per market, regime-log chain check, forward-paper status line, disk). All outgoing text passes the secret filter. Manual: `./run.sh watch watch-check [--summary]`.

### Retention (documented, conservative)
Pruned: `fetch_log` rows older than 90 days (daily job); Hyperliquid position snapshots older than 30 days thinned to one per address/coin/hour (every 6 h). NEVER deleted: regime_log, ledger, news items/features, klines, KIS minute bars, Binance OI/liquidation/funding history, forward registry, research results. Disk alert at 80% used. Current data size is tens of MB, growth about 1-3 MB/day.

### Research (`./run.sh research ...`, `--network none`, 2 GB, 1 CPU, cpu-shares 128, `nice 19`)
`fut-fetch` (public USDT-M klines + funding), `fomc-fetch` (federalreserve.gov calendar), `research-run --study s1|s2|s3_w15|s3_w5|s4`, `forward-eval`. Results in `research/RESULTS_round2.md`, hypotheses in `research/PREREG_round2.md`, forward candidates and success criteria in `research/FORWARD_CANDIDATES.md`.
Cost models (`tp.costs`): futures taker 0.05% / maker 0.02% (BNB -10%), spot 0.1% (BNB 0.075%), sources in the module docstring; fee, slippage, funding, leverage and mmr are independent parameters. `tp.futbt` = isolated-margin USDT-M simulator with real funding and liquidation (analysis only; no order code).

### Time zones
Host = Asia/Seoul (KST, +09:00, NTP synced; it was already KST before this round). Containers stay UTC. EVERYTHING STORED is UTC (ledger, regime_log, hash chain, forward registry, SQLite/parquet times); only display text is KST. KR session logic uses the explicit IANA zone Asia/Seoul (09:00-15:30), the US daily-bar completeness uses America/New_York 16:30 (DST-safe, tested on both sides of the switches).
Scheduler slots are fixed UTC (so they never duplicate): crypto hourly :02; KR 08:30 and 15:40 KST (23:30/06:40 UTC); US 21:30 and 06:30 KST (12:30/21:30 UTC = before the open and after the close in both EDT and EST). Daily budget cap resets at KST midnight (00:00 KST = 15:00 UTC; the window start is earlier than the old UTC day so the switch cannot undercount spend). Daily summary 08:00 KST (= 23:00 UTC). Retention jobs are interval-based (24 h / 6 h), not clock-based. Host timers (dnf-automatic ~06:00 KST, fail2ban) run on local time: they moved from 06:00 UTC-equivalents only if they were configured before the zone change; no action taken.

* Watchdog event log (`src/tp/events.py`): append-only `runs/watch_events.jsonl` (one ASCII-escaped JSON object per line with a UTC `ts` and a `kind`; mode 0600; rotated at 5 MB, 3 files; every write failure is swallowed so logging can never stop the loop). Errors that are not live status go here instead of piling up in `watch_state.json`: every Telegram send failure (class `global`/`client`, HTTP code, short scrubbed description, attempt number, backoff, `retry_after`) and lifecycle events (alert sent/deferred, `telegram_rejected` / `telegram_client_errors` set and cleared, `client_outage`, proposal dropped, state-write failures, forward ERROR rows, KIS counter-reset wait, severity-class changes, `watchdog_degraded`). Descriptions are scrubbed (secrets, tokens, chat ids) and capped at 160 characters; the message body is never intentionally logged. The rolling per-day `send_stats` (attempted / ok / global_fail / client_fail, 7 days) lives in the watch state and never affects `fail_streak`. Read it with `tail runs/watch_events.jsonl`.
* Hermes events digest: `hermesx` writes `export/hermes/watch_events_summary.json` (listed in `MANIFEST.json`, same sanitiser and leak scan as the other files): counts by kind and HTTP code for 24 h and 7 d, first/last seen per kind, the last 30 events and `send_stats`. Hermes gets only this digest, never the raw log.
* Hermes skill deployment: the instructions are `hermes_instructions/SKILL.md` (repo copy). The live copy is `~/trading/hermes/skills/research/pipeline-qa/SKILL.md` on the host (`/opt/data/skills/research/pipeline-qa/SKILL.md` inside the Hermes container), owned by uid 10000 and not writable by the normal host user. Install it with any write that runs as root or uid 10000, then keep the owner and mode (`chown 10000:10000`, `chmod 644`) and write to a temp file in the same directory followed by `mv` so the file is replaced atomically; for example `docker exec -i hermes sh -c 'cat > .../.SKILL.md.new && chown 10000:10000 .../.SKILL.md.new && chmod 644 .../.SKILL.md.new && mv .../.SKILL.md.new .../SKILL.md' < hermes_instructions/SKILL.md`. No container restart is needed, the `pipeline_export` mount stays read-only, and the previous version should be saved first.
