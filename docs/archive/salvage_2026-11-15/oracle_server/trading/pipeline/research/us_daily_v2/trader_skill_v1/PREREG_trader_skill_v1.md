## Universe, data and point-in-time rule
* Universe, calendar, membership spells, eligibility `E`, cost model (10bp/side), execution timing (decision at close t, fill at open t+1), benchmarks (`spy_bh`, `ew_univ`), IS/OOS split, and the panel loader are **100% reused, unmodified**, from `research/us_daily_v2/usbt2.py` (`load_panel`, `sim_targets`, `bench`, `periods`, `sim_start`). This round adds new score/eligibility matrices on top of that unmodified panel; it does not touch `usbt2.py`, `coverage.json`, `is_selection.json`, `oos_results.json`, or any other v2 file.
* New data: SEC XBRL `us-gaap` concept facts, one `companyfacts` JSON per resolved CIK (`data.sec.gov/api/xbrl/companyfacts/CIK##########.json`), fetched once (cached to disk under `research/us_daily_v2/trader_skill_v1/xbrl_cache/`), covering each company's full historical fact history in one call (not one call per quarter).
* Concepts used (fixed now, taxonomy copied from `trader-analyst/facts.py`'s `CONCEPTS` dict, first matching tag per company): `revenue` in [RevenueFromContractWithCustomerExcludingAssessedTax, Revenues, RevenuesNetOfInterestExpense, RevenueFromContractWithCustomerIncludingAssessedTax, SalesRevenueNet, SalesRevenueGoodsNet, SalesRevenueServicesNet]; `cost_of_revenue` in [CostOfGoodsAndServicesSold, CostOfRevenue, CostOfGoodsSold]; `gross_profit` in [GrossProfit]; `eps_diluted` in [EarningsPerShareDiluted, EarningsPerShareBasicAndDiluted]. Only quarterly facts (`fp` in Q1/Q2/Q3/Q4, `form` in 10-Q/10-K) are used; duplicate/amended facts for the same fiscal period keep the latest `filed` date's value.
* **Point-in-time rule (hard, no exception):** a fact is visible to the backtest starting the first trading day strictly after its SEC `filed` date (same-day lookahead is excluded by using `filed`+1 calendar day as the visibility date, then forward-filled to the next visible fact for that concept/company). If a company's `filed` field is ever missing (not expected for XBRL frames, but checked), that observation is dropped rather than substituted with a fiscal-period-end guess.
* Factors (fixed, formulas decided now, not fitted):
  - F1 `rev_growth_yoy`: latest known quarterly revenue / the quarterly revenue reported for the same fiscal quarter one year earlier (both as known point-in-time at date t) − 1. Requires both quarters resolved from the same company.
  - F2 `gross_margin`: latest known quarterly `gross_profit` / same-quarter `revenue`; if `gross_profit` tag absent for a company, computed as `1 − cost_of_revenue/revenue` instead (fixed fallback, decided now).
  - F3 `margin_chg`: F2 today − F2 as of four quarters earlier (both point-in-time known values).
  - F4 `earnings_yield`: trailing sum of the last 4 known quarterly `eps_diluted` values (point-in-time), divided by price `P.C[t]`. Negative or zero -> `NaN` (excluded), matching `trader-screener`'s own rule (`test_no_pe_for_losses`) that no P/E or earnings yield is computed for losses.
  - F5 `quality_composite`: equal-weighted sum of the cross-sectional percentile ranks (within the eligible set that date) of F1, F3 and F4.
* Screener rule `PASS` (fixed now, in the spirit of `trader-screener/screen.py`'s pass/fail semantics): `PASS[t,sym] = (earnings_yield > 0) AND (rev_growth_yoy > 0) AND (margin_chg > -0.02)`. All three thresholds are fixed before any factor is computed. No sweep of these thresholds is performed in this round.

## Strategy rules (12 selection trials; N = 50 names unless noted; ties by ticker; monthly decision, same calendar/fill/cost as v2's `TRIALS`)
* Y1 `xbrl_growth`: score = F1 (`rev_growth_yoy`); top 50.
* Y2 `xbrl_margin`: score = F2 (`gross_margin`) level; top 50.
* Y3 `xbrl_margin_chg`: score = F3 (`margin_chg`); top 50.
* Y4 `xbrl_value`: score = F4 (`earnings_yield`), only positive values eligible; top 50.
* Y5 `quality_composite`: score = F5; top 50.
* Y6 `screener_ew`: equal weight **every** eligible name with `PASS=True` that month, each capped at 2% (so fewer than 50 passers leaves cash) — same construction as v2's `trend_breadth` (X9).
* Y7 `screener_mom`: within `PASS=True` names, rank by v2's `mom12_1` score (12-1 month momentum); top min(50, passers).
* Y8 `screener_lowvol`: within `PASS=True` names, rank by v2's `low_vol` score (lowest trailing volatility); top min(50, passers).
* Y9 `mom_quality`: score = percentile-rank(`mom12_1`) + percentile-rank(F5); top 50 (blended rank, no filter).
* Y10 `xbrl_growth_mkt`: Y1, but 100% cash when SPY close <= SPY SMA200 at the decision (same market filter as v2's `mom12_1_mkt`, X2).
* Y11 `value_momentum`: score = percentile-rank(F4) + percentile-rank(`mom12_1`); top 50 (classic value+momentum blend, no filter).
* Y12 `screener_trend_breadth`: within `PASS=True` names, hold every name with close > SMA200 and SMA50 > SMA200, each capped at 2% (v2's `trend_breadth`/X9 logic restricted to the screener-pass set).

Benchmarks (selection = 0, reused unmodified from v2): `spy_bh`, `ew_univ`.

## Selection, nulls and multiple testing
* Primary metric (identical to v2): annualised excess (over T-bill) Sharpe of daily returns, net of 10bp, ppy 252, IS period = v2's IS (`coverage.json`'s `is_start`..2016-12-30). Selected = highest IS excess Sharpe among Y1-Y12. No re-tuning after seeing results; if none of Y1-Y12 reach the pre-registered gates below, a possible second, equally pre-registered addendum batch (Y13-Y40 at most, filed and timestamped BEFORE its own results are seen) may follow, subject to this programme's hard 40-trial cap (cumulative Y-count across all addenda of this round <= 40). If the cap is reached without a pass, the round ends with an honest "no edge" write-up, matching this program's standing disclosure norm.
* Trial count for DSR deflation: this round's own count is 12 (`n=12`). Cumulative across the whole US daily programme's `trials.sqlite`-logged selection trials: 7 (v1) + 9 (v2) + 12 (this round) = 28 (`n=28`). `REPORT_ma40_us.md`'s one unlogged hypothesis and the uncommitted v3-exploratory round's hypotheses are disclosed above but excluded from `n` for the stated methodological reasons; this is flagged as a limitation, not hidden. DSR computed with both `n=28` and `n=12` (v2's own convention of reporting both the cumulative and the round-only n), using `research/us_daily_v1/usbt.py`'s `dsr_ann` (imported, not re-derived) fed with the actual logged `sr_ann` values read from `runs/research/us_daily_v1/trials.sqlite` and `runs/research/us_daily_v2/trials.sqlite` (selection=1 rows only) plus this round's own new trials logged to a new `runs/research/us_daily_v2/trader_skill_v1/trials.sqlite` (study tag `US_TS1`).
* Random-portfolio null, per strategy, 200 draws: for Y1-Y5, Y9, Y11 (no PASS filter) draw N random eligible names from `E` at the same dates, same N as the real strategy that month, same costs — identical null design to v2's momentum/value-style trials. For Y6, Y7, Y8, Y10, Y12 (PASS-filtered or count-varying rules) the null draws the **same count that the real strategy held that month** from the full eligible set `E` (not from the `PASS` subset) — this directly tests whether the screener filter / fundamental ranking adds value over an equal-count random portfolio, which is v2's own self-corrected, count-matched null design (its post-hoc "gross-cost diagnostic" fix), adopted here from the start rather than bolted on after results, exactly as v2 itself recommended for any future round. p = (1 + #null >= strategy)/(1+200) on OOS excess Sharpe. Bonferroni and Benjamini-Hochberg q across the 12 OOS p-values.
* Paired block-bootstrap (21-day blocks, reusing `research/us_daily_v1/usbt.py`'s `block_bootstrap_ci`) of the daily return difference vs `spy_bh` and vs `ew_univ`, OOS, for every trial.
* Cost sensitivity (5/20/40bp) and decision-phase-shift checks (-5, -10 trading days) are run on the SELECTED winner only (not all 12), logged with `selection=0` (does not inflate the DSR trial count), matching v2's approach.

## Forward-candidate rule for the SELECTED strategy (all must hold; failure is a valid, and the expected, outcome)
G1 OOS excess Sharpe >= `spy_bh`'s OOS excess Sharpe AND >= `ew_univ`'s OOS excess Sharpe.
G2 DSR (n=28, cumulative-programme) >= 0.90.
G3 OOS random-null p <= 0.05 AND Benjamini-Hochberg q <= 0.05 (across this round's 12 OOS p-values).
"Success" for this task = G1 AND G2 AND G3 all hold simultaneously for the selected rule. Any other outcome (including a rule that merely has a positive raw Sharpe, or that beats one benchmark but not the other, or that has DSR in [0.70, 0.90)) is recorded as "no edge, gates not met" — matching the honesty standard already set in `REPORT_us_daily_v2.md` and `REPORT_ma40_us.md`.

Hypotheses (priors, stated so they can be wrong): H1 pure fundamental factors (F1-F4, Y1-Y4) have weak or no cross-sectional power on large-cap S&P500 names, where fundamentals are heavily priced in and widely followed (consistent with v2's general "no edge in this universe" finding); H2 the screener-as-universe-filter rules (Y6, Y7, Y8, Y12) do no better than a random portfolio of the same, time-varying count, because the filter mechanically shrinks and time-varies the eligible set in a way a naive null must match; H3 blended value+momentum or quality+momentum composites (Y9, Y11) do not survive 10bp costs and DSR deflation even if raw IS Sharpe looks attractive, because this is exactly the kind of multi-factor fishing the DSR gate exists to catch; H4 no Y1-Y12 rule passes all of G1-G3 (i.e., the programme's "no edge" finding extends to fundamentals/screener factors too).
