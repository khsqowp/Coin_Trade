# Source_Collector 요청 대화 맥락 및 백테스트 상태

작성 기준: 사용자가 제공한 2,965줄 Claude 세션 복원 텍스트와 현재 Codex 대화. 복원 텍스트는 2026-10-16 세션 조각과 2026-10-24~25 Oracle 작업을 포함한다. 복원 로그 속 실행 결과는 과거 대화에서 주장된 기록이며, 이번 턴에서 재검증한 결과와 구분한다.

## 시간순 기록

### 2026-10-16 — 로컬 Mac 관리

- `mole optimize` 실행 결과: 메모리 스왑 사용률이 높고 WindowServer 및 `com.apple.Virtualization.VirtualMachine` 사용률이 높다는 진단, Prometheus·Redis LaunchAgent가 실행 파일을 찾지 못한다는 경고 등이 보존돼 있다.
- 이 시점의 기록은 Oracle 트레이딩 작업이 아니라 로컬 Mac 최적화 세션이다.

### 2026-10-24 — Oracle 서버 활용 구상

- 사용자는 Oracle 인스턴스를 개인 서버로 쓰려 했고, 기존에 올린 컨테이너를 내리고 다른 것을 옮기려는 계획을 말했다. 대화가 진행되며 전체 제거 대신 Hermes·Freqtrade·수집기를 활용하는 방향으로 전환됐다.
- 후보 서비스로 OpenClaw/Hermes, 저가 LLM API, Telegram, Docker가 검토됐다. 서버는 대화 기록상 ARM64, 2 OCPU, 약 11GB RAM, 173GB 디스크로 설명됐다.
- SSH·fail2ban·자동 보안 업데이트 등 보안 진단이 진행됐고, 사용자는 버그 수정 업데이트만 허용했다. 80/443은 웹 서비스 용도라 닫지 말라고 명시했다.
- 코인과 한국·미국 주식을 함께 연구하고 Telegram을 쓰기로 했다. 코인은 Binance를 선택했다. Freqtrade는 모의 거래(dry-run)로 시작하고 실거래는 금지했다. 사용자는 서버에 API 키를 준비했다고 알렸지만 과거 대화에서 실거래 키는 로드하지 않는 경계가 설정됐다.

### 2026-10-24~25 — 멀티에이전트 연구 파이프라인

- 연구 흐름은 데이터 수집 → Researcher(가설·연구계획) → Engineer(코드·실행) → 독립 Auditor(반증·오류 탐지) → 비LLM Risk Engine 순으로 정리됐다. Binance 공개 시장데이터와 KIS 모의 데이터가 대상으로 언급됐고, 주문 호출 금지와 API 키 비노출 원칙이 붙었다.
- 과거 로그에서 Telegram 토큰이 `.env`의 잘못된 구문 때문에 출력에 노출됐다고 보고됐다. 토큰 교체가 권고됐고, 사용자는 `.env` 권한 처리를 요청했다. 이후 기록상 `~/trading/.env`, KIS·LLM secret 파일을 권한 600으로 맞췄다고 되어 있다. 토큰 교체 여부는 이 텍스트만으로 확인되지 않는다.
- 첫 전략 파이프라인은 BTC 200일 추세전략을 제안·구현했다. Auditor는 통과시켰지만 Risk Engine이 MDD 64%를 한도 35% 초과로 차단했다. ATR 청산 규칙이 실제로 신호에 영향을 주지 않는 dead rule 결함도 발견됐다고 기록됐다.
- 사용자는 `khsqowp/Coin_Trade`의 전략을 참고하라고 했고, 이후 ablation 검증, 전략 인덱스, 단방향 Telegram 알림, Freqtrade 투입 승인 경로를 작업하도록 했다. 과거 완료 보고는 통과 전략 0개, 테스트 79개 통과, Coin_Trade 전략 10개 및 다른 저장소 전략 5개 요약, Telegram 알림 HTTP 200 등을 주장한다.
- Coinglass 연동을 제안하는 과정에서 사용자가 범위 이탈을 지적했다. 이에 연동 작업 지시를 취소하고 제공된 HAR 파일의 네트워크 요청만 분석했다고 기록돼 있다. 이후 사용자는 서버 세팅과 Hermes에 집중하라고 재지시했고, 코인봇을 쓰되 나머지 작업도 진행하라고 했다.

### 2026-10-25 — 전략 연구 라운드 2·3

- 사용자는 당장은 백테스트 목적이고 수주간 결과를 관찰하자고 했다. 5분봉을 배제하지 말고 시장 상황에 맞춰 보유 주기를 유연하게 연구하라고 정정했다. Yahoo 데이터 사용과 개인 비상업 연구를 허용했고, 일일 LLM 예산 $0.30에 동의했다.
- 라운드 2 완료 보고는 현물·선물 비용 모델, 펀딩비·청산 반영 선물 시뮬레이터, 규칙 기반 적응 전략, 스케줄러·워치독, 10개 포워드 후보를 언급한다. 5m·15m·1h·4h 전략을 조사했으며, DSR 보정 후 유의한 후보가 없고 실거래 후보는 없다는 결론이었다. 테스트 176개 통과로 보고됐다. 이 값들은 제공된 복원 로그의 과거 주장이지 이번에 재현한 결과는 아니다.
- 사용자는 약 128.88 USDT를 가정해 보유 종목 하락 시 손절 후 다른 종목으로 교체하는 소액 로테이션을 연구하라고 했다. Hermes가 파이프라인 요약을 읽기 전용으로 답하게 하고, 성과 기준 충족 시 예산 증액을 제안만 하게 하되 실제 승인은 본인이 하도록 지정했다. 실거래는 여전히 금지였다.
- 라운드 3 완료 보고는 25종목, 1시간봉 730일, 66개 변형을 평가했다고 기록한다. 모든 변형이 게이트에 실패했고, 상위 수익 변형은 시작 시각에 민감하며 최대낙폭이 매우 컸다고 결론냈다. 2·3배 레버리지는 청산 또는 대규모 손실이 늘었다. Hermes 읽기 전용 질의 시험 10개와 테스트 203개 통과, 예산 상한 $0.30 유지도 보고됐다.
- 마지막 과거 요청은 작업 종료 후 보고를 받겠다는 것이었다.

### 현재 Codex 대화 — Source_Collector를 Oracle로 옮겨 검사

- 최초 SSH 명령의 계정명이 `ocp`라 `Permission denied`가 났다. 사용자가 계정은 `opc`라고 바로잡았다.
- 사용자는 Oracle의 `/home/opc/ochestration-trading-test`에서 실행해 보라고 했지만, Source_Collector는 서버에 없으니 최신 저장소를 옮겨 그 안의 코인 거래 자료를 백테스트하라고 다시 지정했다.
- 로컬의 오래된 `Source_Collector` 스냅샷은 2026-10-03 `master`였고, 단순 `README.md`와 `raw`만 포함했다. 원격 저장소에서 더 최근 `claude/exciting-fermat-an0557` 브랜치를 발견해 로컬에 shallow clone했다. 대상 커밋은 `41e2bae9f11ca125afcd283ca3dfc7b1bfb7b325`, 커밋 시각은 2026-10-25 03:53:25 UTC다.
- 최신 저장소를 통째로 `/home/opc/Source_Collector_latest`에 rsync했다. 기존 `~/ochestration-trading-test` 및 `~/trading` 경로는 이번 복사에 사용하지 않았다. 서버는 복사 전 `/home/opc` 파일시스템에 153GB 여유가 있었다. 복사 뒤 전체 크기는 2.5GB로 측정됐다.
- 전송 검증: 원본과 Oracle 사본의 `.git/index`, 루트 `README.md`, `Invest/README.md` SHA-256이 각각 일치했다. 서버에는 `git` 실행 파일이 없지만 저장소의 `.git` 디렉터리는 함께 복사됐다.
- 최신 브랜치의 `Invest/README.md`는 `Invest`를 전략 실행 저장소가 아니라 투자 데이터·프레임워크·문서 아카이브라고 설명한다. `qrak/LLM_trader`에는 `README.md`와 ADR README만 있고 봇 구현이 없다. `freqtrade/freqtrade` 경로에도 현재 스냅샷은 README와 백테스트 안내 문서뿐이며, 전략 코드·실행 프로젝트가 없다. Source_Collector 안에서 `Coin_Trade` 또는 `rotation` 파일 경로도 발견되지 않았다.
- Source_Collector에서 직접 실행 가능한 사용자 전략 코드가 없다는 점까지만 확인됐다. 사용자가 공개 데이터로 동일 비교 데이터셋을 만들고 수십~수백 전략을 여러 기간에 시험하라고 범위를 구체화했으므로, 별도 재현 스크립트를 작성해 Oracle에서 백테스트를 실제 수행했다. 저장소 안의 전략을 그대로 실행한 작업과 공개 전략군으로 탐색 실험을 만든 작업은 구분한다.

## 맥락 분석

1. **사용자의 현재 목적은 기존 서버 운영 확인이 아니라 최신 Source_Collector의 코인 전략을 가져와 스크립트 백테스트하는 것이다.** 기존 서버 디렉터리는 전달 대상 위치이며, 기존 Coin_Trade/파이프라인 결과를 새 Source_Collector 백테스트 결과로 대체해 말하면 안 된다.
2. **복원 로그의 과거 라운드 2·3 결과와 이번 작업은 별개다.** 과거 결과는 각각 다른 코드·데이터·가정으로 보고됐고 이번 Source_Collector 실행으로 재현하지 않았다.
3. **최신 Source_Collector의 `Invest`는 수집한 외부 프로젝트와 문서 모음이다.** 백테스트 도구 설명은 있지만 특정 전략을 직접 실행하는 완결된 프로젝트는 현재 확인되지 않았다.
4. **Source_Collector에는 실행 가능한 자체 코인 전략이 없었지만, 공개 데이터 기반 탐색 백테스트로 사용자의 목적을 달성할 수 있었다.** 따라서 결과는 Source_Collector의 특정 내장 전략 성과가 아니라 이번에 작성한 132개 규칙 전략 변형과 세 기준선의 비교 결과다.
