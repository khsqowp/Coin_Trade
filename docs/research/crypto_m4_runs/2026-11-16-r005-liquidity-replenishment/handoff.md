## Causal-integrity follow-up — 2026-11-16

An independent source review found two concrete risks before any strategy labels were calculated: the compact reducer reported aggregate-trade ID gaps but did not drop duplicate/non-increasing IDs, and the prior-aggression quantile filtered only exchange event time, not whether the historical feature had actually arrived by the decision time. The fix is confined to replay/availability logic; no R005 thresholds or performance outcomes were examined.

- Repeated aggregate-trade IDs and non-increasing out-of-order IDs are now excluded from trade-volume calculations and preserved as timestamped feed-error events. The aggregator maps symbol-specific feed errors by exchange event time, making their affected windows fail quality checks. A regression fixture verifies IDs `7,7,6,8` yield only trades `7,8` and explicit duplicate/out-of-order counts.
- Aggregated features now retain both monotonic receive time and persisted receive-wall time. Missing wall receive timestamps invalidate a window. The candidate builder requires completed T/H bars and windows to be strictly available before both decision anchors. Prior aggression rows with an earlier exchange event but a receive-wall time at/after the decision are excluded from the threshold.

## Independent follow-up defect and fix — 2026-11-16

- The independent reviewer found that a symbol-specific feed error with malformed exchange-event time but a valid receive-wall time could be assigned to the wrong 10-second window. The aggregator now refuses that attribution, records the affected symbol under `unknown_time_feed_symbols`, and fails the manifest quality gate. Candidate construction now requires the aggregation manifest itself, rejects a failed global gate, validates its invalidation list, and derives late-invalidated windows from that list rather than relying on a caller-created set.
- A second review found that a caller could mismatch a quality-passing manifest and windows. The aggregator now derives a run ID from source/code/configuration, stamps it and a row SHA-256 on each emitted window, and the candidate builder verifies the aggregator code hash against the current module, recomputes the run ID from manifest source/code/configuration fields, validates quality flags against failure counters, validates every row hash and invalidation list, and checks the full ordered JSONL output hash before candidate construction. The manifest also carries an unkeyed integrity hash; it detects incidental edits but is not a signature and cannot authenticate a coordinated rewrite. This requires the complete window output in memory; chunked/sharded replay is not implemented.
- Regression coverage now includes malformed event timestamp with a valid receive timestamp, candidate abstention on a failed aggregation manifest, late-invalidated finalized-window gating, equal monotonic availability exclusion, mismatched run identity, and modified-row checksum rejection.
