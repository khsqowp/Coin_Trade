# R019 OHLC-path method-only simulation — preregistration

Status: frozen before this simulation. It validates deterministic execution/path mechanics only; it is not a strategy test and opens no market outcomes.

## Objective

Independently validate `chart_predictor.crypto_divergence_engine.evaluate_divergence_event` against a scalar reference for the divergence study's registered 1-minute execution path. Cover every registered native timeframe (1, 5, 15, 30, 60 minutes), both 10/20-native-bar horizons, long/short, next-open/stop-entry, target R values (1, 1.5, 2, 3), both registered stop buffers (0, 0.25 ATR), base costs, and 2x-slippage stress costs.

## Frozen synthetic design

- Generate only artificial, valid OHLC paths from a fixed pseudorandom seed `20261127`. No historical or live candle/trade row, exchange response, price label, strategy output, or raw archive is an input.
- Run 200 scenarios in each of the 40 cells `native_tf_minutes × horizon_bars × side × entry_mode`, for exactly 8,000 scenarios. In each cell, for zero-based scenario `j`, set `target_r = (1.0, 1.5, 2.0, 3.0)[j % 4]` and `stop_buffer_atr = (0.0, 0.25)[(j // 4) % 2]`; this yields 25 cases for each target/buffer pair. Do not select cases by execution outcome.
- Use one standard-library `random.Random(20261127)` instance for the complete ordered suite, with Python 3.13.5; use no other random source. Iterate cells in order `(1,5,15,30,60) × (10,20) × (long,short) × (next_open,stop_entry)`, then scenario order `j=0..199`. Reset each scenario's first log-price to `log(100)`. Generate exactly `timeframe_minutes × (3 + horizon_bars)` consecutive minute bars per scenario, consuming exactly two `.random()` draws per bar. For each minute, set open to the previous close; draw `u` and set log-close to `log(open) + 0.008*(2u-1)`; draw `v` and set `span = 0.001 + 0.009*v`; set high to `max(open,close)*exp(span)` and low to `min(open,close)*exp(-span)`. Close becomes the next minute's open. Aggregate only complete UTC-aligned native buckets: first minute open, maximum high, minimum low, last minute close. Use ATR exactly `0.01 × signal_close`; desired effective stop is `signal_close × (1 − 0.005)` for long or `signal_close × (1 + 0.005)` for short. Set long `pivot_stop = effective_stop + stop_buffer_atr × ATR`; set short `pivot_stop = effective_stop − stop_buffer_atr × ATR`. The production evaluator then applies the preregistered adverse buffer and obtains the desired effective stop. The signal trigger is the signal native-bar high for long or low for short. Start stop-entry scanning in the native bar immediately after the signal bar. After any fill, the outcome horizon starts at the first minute of the actual entry native bar and includes that entry bar as bar 1; it covers exactly `timeframe_minutes × horizon_bars` consecutive 1-minute bars total, not that many bars after entry. Consequently `timeframe_minutes × (3 + horizon_bars)` bars cover the signal bar, all three possible activation bars, and the full outcome horizon even when the third activation bar fills. These are artificial mechanics fixtures, not sampled market paths.
- Implement a separate scalar oracle module that imports no production evaluator, path resolver, net-R function, or production helper. It must independently validate aligned timestamps/OHLC, aggregate native bars from minute bars, derive effective stop/trigger, scan next-open or the next three complete native bars for stop-entry, and resolve the post-entry path minute by minute. For generated valid scenarios, build production inputs with the repository's production minute aggregation function, independently rebuild native bars in the oracle, and require exact timestamp/OHLC equality before comparing execution outcomes. Sentinels intentionally corrupt minute input after constructing their valid native fixture, so they are evaluated for fail-closed behavior rather than aggregate equality. Adverse stop gaps fill at the observed open; favorable target gaps fill at the target; same-bar stop/target ambiguity resolves stop-first. For stop-entry, validate each pre-entry activation minute's finite OHLC and OHLC ordering before considering its trigger: malformed activation data returns `unresolved`; otherwise process each minute in order, where an open through the trigger fills at that open before checking invalidation, stop/invalidation before an intraminute trigger touch produces `no_fill_invalidated`, and an intraminute trigger fills at the trigger. The oracle must calculate costs and net R from first principles. A reviewer must verify the oracle source has no imports/calls to production execution helpers and independently inspect the sentinel expected values before execution.
- Evaluate each synthetic event twice with identical path and entry settings: fee 0.05% per side plus 0.025% adverse slippage per side (base), and the same fee plus 0.05% adverse slippage per side (stress). Raw entry/exit prices are not rounded or rewritten. For each side define `c = fee_per_side + slippage_per_side` and `risk = abs(entry_price − effective_stop)`. Independently calculate long `net_R = (exit_price*(1−c) − entry_price*(1+c))/risk`; calculate short `net_R = (entry_price*(1−c) − exit_price*(1+c))/risk`. Do not round intermediate values. Costs are assumptions, not observed market friction.
- Add deterministic sentinels separate from the 8,000 randomized scenarios. Canonical sentinel fixture: 1-minute bars at `t=0..12` minutes; every ordinary bar has O=C=100, H=101, L=99; signal bar has H=102 for long / L=98 for short; long stop=90 / short stop=110; ATR=2, buffer=0, target=1R, horizon=10. For each sentinel, assert the complete tuple `(status, target_first, entry_ms, entry_price, exit_ms, exit_price)`; `t` values below are minute indices and all prices are exact:
  - Long next-open adverse gap: bar t=2 is O=89,H=100,L=88,C=95 → `stop, false, 1,100,2,89`.
  - Long next-open favorable gap: bar t=2 is O=111,H=112,L=109,C=111 → `target, true, 1,100,2,110`.
  - Long same-bar stop/target tie: bar t=2 is O=100,H=111,L=89,C=100 → `stop, false, 1,100,2,90`.
  - Long timeout with untouched barriers → `timeout, false, 1,100,10,100`.
  - Long stop-entry no fill (ordinary highs stay 101 below trigger 102) → `expired, false, null,null,null,null`.
  - Long stop-entry gap through trigger: bar t=2 is O=103,H=104,L=102,C=103 → `timeout, false, 2,103,11,100`.
  - Long invalid stop: pivot stop=100 → `invalid, false, null,null,null,null`.
  - Malformed bar at t=2 (H=98 with O=C=100) → `unresolved, null, 1,100,null,null`.
  - Stop-entry malformed activation bar at t=2 (H=98 with O=C=100), after t=1 remains a no-trigger ordinary bar → `unresolved, null, null,null,null,null`.
  - Duplicate t=5 timestamp (replace it with t=4) → `unresolved, null, 1,100,null,null`.
  - Omit t=1 (the first required minute, before the entry is established) → `unresolved, null, null,null,null,null`.
  - Separately omit t=5 or t=10 after the entry open has been established → each `unresolved, null, 1,100,null,null`.
  Mirror the adverse-gap, favorable-gap, tie, and stop-entry-through-trigger cases for short with prices reflected around 100 (stop 110, trigger 98, target 90); expected exit prices are respectively 111, 90, 110, and stop-entry timeout entry 97 / exit 100 at t=11. Each sentinel mutates only its stated field; expected output is fixed before running.

## Pass/fail criteria

The method gate passes only if all 8,000 scenarios and every sentinel complete; the production evaluator and independent oracle agree exactly on status, target-first label, entry timestamp/price, exit timestamp/price, and agree on net R within absolute tolerance `1e-12` for both cost schedules; all deliberate missing/corrupt inputs return unresolved (or the preregistered invalid/no-fill state) rather than a fabricated outcome; and a second run in the same Python 3.13.5 environment produces byte-identical aggregate JSON. Serialize UTF-8 JSON with sorted keys, compact separators `(',', ':')`, no wall-clock fields, and exactly one terminal newline. Any mismatch, numerical error, skipped case, or nondeterministic result is a failure. Preserve failures; do not alter seed, scenario count, distributions, or tolerances after observing them.

## Interpretation boundary

A pass validates only the tested path resolver and cost arithmetic under synthetic fixtures. It does not validate real fills, bid/ask spread, slippage, funding, liquidation, data completeness, target-first performance, the R019 inference procedure on a market claim family, or any trading signal. In particular, the divergence preregistration's 20-claim/40-contrast family is not certified by R019's 24-claim/48-contrast synthetic calibration. No market-label access is authorized by this test.
