# User Pine indicator audit and macro-to-micro candidate

Date: 2026-11-15. This is a source/method review only. No backtest, performance estimate, data query, strategy implementation, external call, or order was made for this audit. Three independent research agents reviewed the supplied Pine source and the prior research summary; all recommended withholding a new performance run until the timing rules and independent evaluation data are fixed.

## Decision

Do not backtest the supplied Pine defaults. Treat the script as a visual sketch, not a valid macro-to-micro strategy. Carry forward at most one hypothesis: **a previously completed higher-timeframe market-structure regime gates a strictly later lower-timeframe sweep-and-MSS setup**. This is a candidate draft, not a frozen preregistration and not evidence of profitability.

The reason to defer is specific: earlier crypto tests already exhausted many breakout, squeeze, momentum, volume, EMA, Heikin-Ashi, and multi-timeframe filter combinations, generally with poor target-first rates or negative cost-adjusted expectancy. A new run on the same already-opened historical cache cannot validate the 80% objective. It would be useful only as a declared exploratory rejection screen, which is not justified until the candidate and execution semantics are complete.

## Defects in the supplied Pine source

1. **There is no macro direction filter.** The script's higherTimeframe input only determines a number of chart bars. `ta.highest(high, barLength)[1]` and its low equivalent compute a rolling range from chart-timeframe bars; they do not request a completed higher-timeframe bar or determine an HTF trend regime. For timeframes that do not divide evenly, integer division can silently produce a different range length.
2. **The event sequence can collapse into one bar.** The sweep detector changes state from `Waiting` to `Waiting For MSS`. A later independent `if` statement then sees the new state and can test the MSS condition on that same bar. This does not prove sweep first and structure shift later.
3. **The entry-bar path can be scored before the entry.** After the script sets state to `Entry Taken`, a following independent block checks the current bar's full high/low for TP or SL. The OHLC bar may have reached those extremes before the intrabar entry. A bar-close entry cannot use that bar's earlier range at all.
4. **The Wick fill price is not established by OHLC.** Assigning the MSS level as the entry assumes the within-bar path and fillability. If the bar opens beyond the level, or traverses stop/target before entry, the source has no way to recover event ordering.
5. **Ambiguous barriers are resolved optimistically.** If TP and SL are both in a bar's range, the code checks TP first. The research scorer must use lower-timeframe path data where available and otherwise resolve ties stop-first, with adverse gap fills.
6. **The setup and trade have no timeout.** A sweep can wait indefinitely for MSS; after entry, the position remains open until TP/SL. Stale states and unbounded holding periods violate the requested 10–20-bar prediction window.
7. **Default reward/risk is poor.** Fixed defaults set TP=0.3% and SL=0.4%, a 0.75:1 reward/risk ratio; the separate RR=0.9 only applies in Dynamic mode. Before costs, the fixed bracket needs 57.14% target-first wins to break even. With an assumed 0.10% round-trip fee, simplified break-even rises to 71.43%: `(.4% + .1%) / (.3% + .4%)`. This excludes slippage, funding and gaps. TP/SL modes must not be swept after seeing outcomes.
8. **Alerts can repeat while a trade is open.** `entrySignalLong` and `entrySignalShort` are persistent `var` values. Once set true, the code does not reset them every bar; alerts and shapes may therefore remain active until the position closes.
9. **A sweep is not required to fail.** High/low crossing the rolling level is enough; the signal does not require a close back inside the range. A continuation breakout can therefore be labeled a liquidity grab and set up a countertrend trade.
10. **Exit alert conditions are likely unreachable.** The code assigns `Take Profit` or `Stop Loss` and then replaces the strategy object with a fresh `Waiting` object before the final `alertcondition()` calls inspect its state. The final TP/SL alert conditions therefore see the reset state, not the transient exit state.

## Single candidate for a future preregistration

This draft follows the user's requested top-down sequence and changes only the event semantics necessary to make it testable. It is not approved as a live signal and has no result yet.

- **Macro regime:** BTC 4-hour structure, derived only from fully completed 4-hour OHLC bars. A possible deterministic definition is two confirmed 2-left/2-right pivot highs and lows: bullish only when the latest two confirmed highs and lows both rise (HH+HL); bearish only when both fall (LH+LL); otherwise neutral. A pivot becomes usable only after its right-side confirmation bars have closed. Neutral means no signal. This exact regime rule must be accepted and frozen before a prospective evaluation begins.
- **Micro timeframe:** one fixed 5-minute execution chart, not a search across intervals. Its intended forecast window is 10 bars (50 minutes), satisfying the requested 10–20-bar horizon without selecting the best horizon after the fact.
- **Sweep:** on an individual coin, after a BTC regime is known, a 5-minute bar must pierce the prior 12 completed 5-minute bars' high/low (one-hour reference range) and close back inside. Only a downside sweep can qualify for a long in bullish BTC regime; only an upside sweep can qualify for a short in bearish regime.
- **MSS and sequencing:** the sweep bar only arms the setup. Starting on the next completed 5-minute bar, a long requires a close above the highest high of the four preceding completed 5-minute bars; a short requires a close below the four-bar low. Confirm only one first MSS, expire the armed setup after 12 subsequent 5-minute bars, and never allow same-bar sweep/MSS. The exact swing/level confirmation must be tested for prefix invariance before any outcome run.
- **Entry and risk:** enter at the next 5-minute open after the confirmed MSS close. Stop is the sweep-bar extreme, rounded conservatively to the symbol's tick size. Reject the setup if the next open is already through the stop. Target is 2R (target:stop = 2:1), fixed in advance; do not inherit the Pine 0.75R fixed bracket or its dynamic RR choice. One open trade per symbol; no overlapping signal is counted until exit.
- **Exit:** resolve barriers starting after the entry fill. Use 1-minute OHLC to resolve 5-minute paths where present; if both barriers are touched within a 1-minute bar, stop first. Fill a stop gap at the adverse open. If neither target nor stop occurs, exit at the close of the 10th 5-minute bar. The round-trip fee assumption must be frozen before testing; use the existing project assumption only if it is still valid for the account's actual fee tier. Funding near settlement and the omission of slippage must be reported explicitly.
- **Population and statistic:** freeze the 20+ symbol cohort before prospective collection and preserve inclusion/delisting eligibility. Count unique non-overlapping events, cluster uncertainty by UTC day and macro-regime event, and compare against matched same-anchor momentum, fixed-seed random direction and flat/no-trade baselines. Confidence filtering/calibration must be learned on development data before the final set is opened; it cannot be improvised after seeing the outcomes.

The above is a research proposal only. The exact fee tier, eligible symbol cohort, data feed/candle-finalization boundary, confidence calibration method, and the independently sealed/forward collection period are not established here. If any remains unresolved, do not run the decisive test.

## Evidence and gates before the decisive test

1. Write an immutable preregistration containing the regime and pivot confirmation timestamps, sweep and MSS definitions, symbol cohort, 5-minute interval, 10-bar expiry, stop/target/costs, overlap rules, baselines, calibrated-confidence threshold, trial count, code SHA, and data/access boundary.
2. Establish an append-only prospective signal/outcome ledger before examining aggregate results. The previous local candle databases and historical reports have already been exposed; do not relabel them as sealed.
3. Prove time alignment with prefix invariance, future mutation, a deliberate future-peek negative control, missing-minute and incomplete-HTF-bar tests, same-bar stop-first and adverse-gap fixtures.
4. Do not open the final set unless the frozen system can support at least 200 non-overlapping selected events across at least 20 symbols and the pre-registered 10% coverage floor. Insufficient sample is `INCONCLUSIVE`, not a reason to tune the same holdout.
5. Success requires M4 point precision at least 80%, Wilson 95% lower bound above all matched baselines, positive fee-adjusted expected R, and the coverage/sample gates above. Open the final set once. Any rule change consumes that holdout.

## Prior results that prohibit a casual parameter search

Earlier development experiments covered breakout/squeeze/momentum grids, AVWAP and ATR expansion with higher-timeframe alignment, volume-climax failure, Heikin-Ashi continuation, EMA pullback, taker imbalance, BTC lead/alt lag, liquidity sweep/taker flow, and candle streaks. Across representative fixed-rule tests, target-first rates were commonly about 20–50%, net expectancy was usually negative, and notable cells failed coverage or sample requirements. These results do not prove that every sequential sweep→MSS rule fails, but they make any post-hoc selection of the best timeframe, RR, MSS length, or confidence threshold especially unreliable.

## Agent synthesis

Three independent reviewers agreed: the Pine source is not causal enough to test as written; the macro regime must be a separate, completed-HTF decision; sweep and MSS must occur on distinct completed LTF bars; entry must follow confirmation; and ambiguous OHLC outcomes must never be resolved in the strategy's favor. They did not produce or claim performance metrics. One reviewer suggested a simple HTF candle-color filter; it was not adopted because a single candle color is a weak, potentially noisy regime definition. The structure-based proposal above is more aligned with the user's macro-first request, but remains untested and requires a sealed forward evaluation.
