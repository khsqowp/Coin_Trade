# Round 3 — 데이터 수급·수집 설계 게이트 (2026-11-16)

## 판정 범위

이 문서는 데이터 소스 조사와 수집 구조 제안이다. API 계정 발급, 샘플 요청, 데이터 구매·다운로드, 실시간 수집, NAS 쓰기, 서버 배포는 수행하거나 승인하지 않는다. Binance 공개 시세 스트림은 연구용 신호 수집 후보일 뿐 주문 권한을 쓰지 않는다. 현 시점 성과 백테스트는 0건이다.

사용자 고정 기준은 다음과 같다.

| 시장 | 합격 기준 |
|---|---|
| 한국·미국 주식 및 ETF | 별도 포트폴리오 기준 CAGR ≥20%, MDD ≤30%, 연환산 Sharpe ≥1.0, OOS 청산 거래 ≥200건 |
| 코인 무기한 선물 수동 신호 | 주 지표: 목표가가 손절/무효화보다 먼저 체결 가능한 가격으로 도달한 비율 ≥80%; 사전등록된 비중복 OOS 이벤트 ≥200건. 만기 시 방향 정확도는 별도 보고 |

주식 전략 성과 비교 전 기준지수, 배당·분배금 재투자, 세금·수수료·슬리피지, 포지션 크기, 리밸런스, 동시 포지션 및 현금 규칙을 사전 고정해야 한다. 코인은 신호 봉 기준 10배 및 20배의 시한을 별도로 평가한다. 미완성 봉은 배제하고, 다음 실행 가능 가격으로 진입한다. 한 봉 안에서 목표·손절이 모두 닿으면 손절 우선으로 계산한다. 만기 종료는 목표 도달로 세지 않는다.

| 시장/후보 | 확인된 범위 | 아직 입증되지 않은 것 | 게이트 |
|---|---|---|---|

KRX는 키 발급 및 이용조건에 비상업 제한, 일일 호출 제한, 제3자 제공 제한, 완전성 보장 부재가 명시되어 있다. 개인 내부 연구에서의 보관·파생 지표 범위는 원문 조건에 따라 추가 확인이 필요하다. 샘플·견적 조회 허용은 받았지만 외부 연락에 사용할 신원/계정 승인은 없으므로 아직 문의하지 않았다. CRSP·TAQ도 샘플이나 라이선스가 확인된 것으로 쓰지 않는다.

## 코인 신호 데이터 제안 — Binance USDⓈ-M 공개 스트림

최신 공식 문서는 USDⓈ-M 공개 스트림을 `market`와 `public` 경로로 나누어 기술한다. 구현 전에 사용하는 각 스트림의 최신 카탈로그 페이지와 상품 계약을 다시 확인한다.

| 데이터 | 활용 | 관측 제한·오류 처리 |
|---|---|---|
| Aggregate trades | 거래 이벤트 기반 1초 OHLCV·매수/매도 체결흐름 파생 | 집계 거래 스트림이지 개별 체결 전체 원장이라고 단정하지 않는다. 교차 연결/시퀀스 결손 구간은 불완전 표시 |
| Kline | 공식 시간봉 및 종가 확정 이벤트 | 닫힘 플래그가 확인된 봉만 신호 입력. 10분·연봉 등 거래소 표준 목록에 없는 주기는 UTC 경계 기준 로컬 집계로 만들고 집계 코드를 버전 고정 |
| Mark price/funding | 마크·지수·현재 펀딩/다음 펀딩 보조 맥락 | 체결 가격과 구별한다. 이벤트 시각과 로컬 수신 시각을 함께 기록 |
| 개별 심볼 bookTicker | 최우선 bid/ask·잔량 및 스프레드 특징 | RPI 주문은 데이터에서 보이지 않는다. 이벤트 간 결손·장애를 정량화 |
| 전 종목 `!bookTicker` | 유니버스 감시용 보조 스냅샷 | 공식 문서의 갱신 속도는 5초다. 개별 심볼 실시간 이벤트를 대체하지 않는다 |
| Diff depth | 주문장 불균형·깊이 변화 | update ID `U/u/pu` 연속성을 검증한다. snapshot과 이어붙이기 실패 또는 `pu` 단절 시 해당 심볼의 주문장 특징을 무효 처리하고 재동기화 |
| 청산 스트림 | 청산 이벤트 보조 특징 | 전 종목 스트림은 심볼별 최신 주문만 짧은 구간에서 전달되는 제한이 있어 전체 청산 테이프로 취급하지 않는다. 과거 공개 기록도 보장하지 않는다 |

현 USDⓈ-M 연결 문서에는 연결당 24시간 만료, 서버 ping 프레임 및 pong 응답 요구, 연결별 초당 수신 메시지 한도가 있다. 24시간 직전 선제 교체와 예기치 않은 종료 재연결은 운영 설계에 포함하되, 재연결은 유실 데이터 복구를 뜻하지 않는다. 끊김 구간은 결측으로 남기고 REST 보충 가능성·권리·시점 정합성을 별도 검증한다. 복구가 확인되지 않은 구간은 학습·평가에서 제외한다.

각 원시 이벤트에 거래소 이벤트/거래 시각, 로컬 UTC wall-clock 및 monotonic 수신시각, 연결 ID, 심볼·상품형, 스트림, 시퀀스 ID, 파서·스키마 버전을 저장한다. 원시 파일은 UTC 시간 파티션으로 기록하고, 1초 봉은 거래를 집계해 생성한다. 분·시·일·주·월·년 봉은 이전 주기의 닫힌 봉만 합성한다. 월·년은 UTC 달력 경계로 고정한다. 불완전 구간을 0으로 채우거나 직전 가격으로 덮어 평가하지 않는다.

### 제안된 적격성 검사

1. 계약 목록을 시점별로 저장하고 USDT quote, perpetual, trading status 및 USDⓈ-M 상품형을 명시적으로 검증한다. 티커 상위 종목을 고를 경우 선택 시점의 정보만 이용하고, 과거로 현재 상위 순위를 소급 적용하지 않는다.
2. 실시간 수집 후보 유니버스 20개 이상을 사전에 고정하거나, 20개 미만이면 사용자에게 정한 MTF 범위의 외삽 검증을 수행하지 않는다.
3. 각 봉 주기 × 10배/20배 시한 × 롱/숏/레짐별로 이벤트 정의와 비중복 규칙을 고정한다. 겹치는 신호를 독립 거래 수로 부풀리지 않는다.
4. 각 주장별 OOS 비중복 이벤트가 200 미만이면 80% 합격을 선언하지 않는다. 80% 점추정 외에 이항 신뢰구간, 목표 미도달률, 손절/무효화 선도달률, 만기 방향 정확도, 수수료·스프레드·슬리피지 반영 결과를 병기한다.
5. 후보 선택과 규칙 변경은 개발/검증 구간 안에서만 한다. 최종 미사용 holdout은 한 번만 연다. 모든 비교군·파라미터 조합 수를 기록하고 다중비교 보정을 적용한다.

### 저장·운영 제안 — 구현/수집 승인 아님

기존 사용자 보관 규칙을 설계 요구로 반영한다: Mac/서버 로컬 스풀에 활성 데이터를 쓰고, UTC 날짜가 닫힌 뒤 체크섬·manifest를 만들며, `/Volumes/HDD2TB/Trade`에 복사한 뒤 원격 파일 크기와 SHA-256 검증을 통과한 파일만 로컬에서 지운다. NAS가 마운트되지 않으면 로컬 backlog를 보존한다. 날짜 경계, 동시 기록 파일, 프로세스 중단, 디스크 용량 임계값, 중복 업로드, 삭제 재시도, 재연결 갭을 실패 주입 테스트로 검증해야 한다. 이번 라운드에서는 NAS 접근·파일 쓰기·삭제를 수행하지 않았다.

## 라운드 상태 / 결정

- 현재 조건부 규칙 심사 후: 통과 0, 반려 21, 조건부 9. 조건부 중 4개는 허용된 1회 수정에서도 정의 결함이 남아 반려 처리했다.
- 주식/ETF 성과시험: 0건. 시장별 필수 커버리지·권리·거래비용 기준이 미완료다.
- 코인 신규 OOS 목표선도달 성과시험: 0건. 기존 탐색 자료는 새 합격 표본으로 재사용하지 않는다.
- 실시간 수집, 계정/API 키, 주문, 외부 데이터 구매, 서버 배포: 수행하지 않았다.
- 다음 허용 연구 단위: 4개 독립 역할(KR, US, crypto, red-team)이 전략/데이터 프로토콜과 사전등록 규칙을 작성하고 교차검토한다. 데이터 적격성 게이트가 열리기 전에는 반복 성과 백테스트를 돌리지 않는다.
