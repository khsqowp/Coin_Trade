## 0. 먼저 결론 (10줄)

1. **세 팀 모두 재현된다.** R2A(smoke 23 assert, f*=0.6341, P75=0.0930/0.0409), R2B(RMSE 0.039%, λ 0.209, 1분 재판정표 비트 동일), R2C(V0 패리티, power.out 동일, 전 셀 수치 diff=0)를 내 쪽에서 다시 돌려 일치했다. 해시 로그도 선언된 수정 외에는 일치. 다만 **재현 = 코드가 같은 숫자를 낸다**는 뜻이지 모델이 라이브와 같다는 뜻이 아니다.
2. **가장 큰 구조적 결함(세 팀 공통, 신규, 내가 계량함): 연구 엔진은 "수량 유지(kept-qty) V0"이고 라이브는 "리밸런스마다 보유 포지션을 목표 명목으로 리사이즈(허용오차 15%)"이다.** R2A 가 후보로 기각한 `C1_norm` 이 사실상 라이브 규칙이다. 그 규칙 하에서 날짜이동 청산확률(f=.75, anti)은 0.093 → 0.015(-84%), 킬 횟수 4.0 → 2.9. 반대로 성장은 OLD 에서 현재 셀 CAGR 74.5% → 41.3%(-0.21 ln/년, 내 재실행). R2B 의 "기대 CAGR +62%"도 V0 값이다. 방향이 한쪽으로 정해지지 않으므로(NEW 는 +0.08) **성장 수치는 전부 '모델 불일치 + 카오스' 대역으로만 읽어야 한다.**
3. **R2B 의 핵심 발견은 강하다**: 시간봉 앵커스(롱 저가·숏 고가 동시) 모델은 비현실적으로 비관적이다. 1분 마크 재생에서 4x/5x/6x 모두 30개 부분집합 청산 0(시간봉 모델은 1/8/12). 6일 스트레스에서 롱·숏 바스켓 1분 PnL 상관 -0.79~-0.99. 내가 R2B 의 stress.json 으로 환산한 **플래시 청산 임계 총노출/자본 G\* 는 6일 중 최소 18(1분 L/H동시 기준)** 으로 현행 3.8 의 4.8배, 킬 상한 5.85 의 3.1배다(선형 외삽, 6일 표본, ADL 미반영).
4. **2026-10-12 킬은 가짜 킬이 맞다**(dd 20.4% 가 44.5% 로 계산됨). 단 **원인(커서 후퇴)은 여전히 미확인**이고, 코드에는 그것 말고도 **같은 계열의 결함 4개**(H1~H4, 4절)가 있다. 격리 테스트(28개)에서 원본 복사본이 사고를 그대로 재현했고(`hwm 244.19, dd 0.445, flatten 호출`), 제안 패치 복사본은 막았다. **심각도: CRITICAL(라이브 안전, fail-dangerous 변형 존재).**
5. **"안전 비대칭"(R2C)은 사실이지만 설명이 틀렸다.** OLD(소유자 유사 유니버스)에서는 현재 셀도 kill-none 도 2025-10-10 에 *똑같이 보유 중*(48/48, gross/eq 2.95~3.06)이고 둘 다 청산 0 이다 — 운 좋게 낮은 gross 였기 때문이다. 비대칭은 NEW(2021-01-11/02-15 에 킬 셀은 flat, 무킬 셀은 gross/eq 6.9~8.1) 와 OLD-PIT(2025-11-06 등)에서 나오며, 이는 "플래시 방어"가 아니라 "gross/eq 폭주 방지(상태 방어)"다. 그 폭주는 V0 kept-qty 에서 과장된다.
6. **OLD-PIT 파산(AIA +332%, MYX +298%, SIREN, GIGGLE +145%)은 소유자의 큐레이션 45종목에는 없는 펌프 코인 때문**이다. PIT 멤버-일 중 일 수익률 > +60% 40건 중 소유자 45종목은 2건(XRP 2023-07-13 +73%, ADA 2025-03-02 +72%)뿐. 반대로 소유자의 45종목은 사후 큐레이션이라 ZEC 가 PnL 의 63%(R2C S1) — 양쪽 편향이 반대 방향이다.
7. **후보 분류**: 성장 개선이 *지지*되는 후보는 없다. 4x→5x, 킬 .5/.6/무킬, 구조적 캡 모두 "uninformative 또는 unsupported". 지지되는 것은 **가짜 킬/이체 처리 수정(공학적 증거)** 뿐.
8. **MDE 해석 정정**: R2A 의 "MDE 1.9/년"은 절대 g 의 SE 로 쌍체 차이를 검정하는 오류(5~10배 과대). 쌍체 SE 는 0.01~0.14 → MDE 0.03~0.4. 결론(미검출)은 같지만 숫자가 틀렸다. R2C 의 MDE(0.28~2.6 vs 목표 0.05~0.12 → 30~190년)는 맞다(재현).
9. **라운드 3: NO-GO(최적화 목적).** 더 백테스트해도 결정되지 않는다. 비백테스트 조치 3개가 위험을 가장 줄인다(7절). 소유자가 "청산 불가"의 꼬리 증거를 더 원할 때만 쓸 수 있는 **선택적 서술적 재생 1건**의 사양을 부록으로 둔다(결정을 바꾸지 못함).
10. **정직한 확신 수준**: 아래 표 참조. 100% 는 불가능하며, 특히 "청산되지 않는다"는 6일 1분 표본·0건 관측으로는 통계적으로 입증 불가(규칙 3의 법칙: 사건 n 건 무관측이면 95% 상한 3/n).

## 6. 소유자 목표와 증거의 내적 비일관성 (중립 서술)

1. **"청산 불가"는 통계적으로 입증 불가.** 스트레스 무관측 n 건에 대한 95% 상한은 3/n. 우리가 가진 독립 플래시 사건은 사실상 1~6건(10-10, 12-09, 05-10, 08-05, 2022-05-11, 2025-02-03)이라 상한은 50% 이상이다. 구조적 논거(헤지 북, 1분 G\*≥18 vs 현행 3.8)가 근거이며, 이는 ADL·API 장애·거래소 이벤트를 포함하지 않는다.
2. **"수익 최대"와 "킬 .35 유지"는 충돌하는 방향의 증거를 가진다**: 백테스트상 킬 .35 는 OLD 에서 -0.13~-0.26 ln/년의 비용(live-like -0.13, V0 -0.21~-0.26)이고 편익은 소유자 유니버스에서 관측되지 않는 사건(펌프 스퀴즈)에 대한 보험이다. 보험료를 낼 가치가 있는지는 데이터로 결정되지 않는다(선호의 문제).
3. **"레버리지 상향 개방"**: 5x 는 성장 이득 증거 0, 킬 빈도 +38%, OLD-PIT 에서 유의한 손해. 플래시 청산은 역사상 구속적이지 않으므로 "위험해서"가 아니라 "이득 근거가 없어서" 올릴 이유가 없다. **"하향 불가"**도 증거 기반 결론이 아닌 선호다(3x 가 4x 와 구별 불가, R1 동일).
4. **"청산되지 않는 것"의 실제 위험은 레버리지 숫자보다 운영 실패다**: 실제 관측된 사고는 시장 청산이 아니라 가짜 킬 1회/8주, IP 밴(10-11 418), recvWindow 오류(10-24), 방치 스레드 결함 가능성(M17)이다.
5. **정직한 확신**: 위 5절 "강/약/미지" 구분 이상은 주장하지 않는다. 특히 현행 셀의 장기 CAGR(41~75%)과 5x/킬 변경의 우열에 대해서는 방향 확신 <60%.

## 7. 라운드 3 판단

**결론: 최적화 목적의 라운드 3 는 NO-GO(루프 종료 권고).** 사유(수치): (i) 후보 11개 모두 MDE 0.28~2.6/년 vs 목표 0.05~0.12/년 → 결정에 필요한 표본 29~190년(R2C, 내 재현), 쌍체 SE 로 정정한 R2A 도 최소 0.03~0.4/년; (ii) 레버 순서가 표본마다 부호가 바뀜(5x: OLD -0.02, NEW ±, OLD-PIT -0.4); (iii) 모델 충실도(M1)가 후보 효과(0.05~0.12)보다 큰 -0.2/년 규모의 구조적 불확실성을 만든다; (iv) 가능한 새 데이터(2019-09~2020-02, 6개월)로는 MDE 가 의미 있게 줄지 않음. 핵심 의사결정(“킬 .35 유지/5x/무킬”)은 선호·위험 허용도의 문제이고 백테스트로 결정되지 않는다.

**위험을 가장 많이 줄이는 비백테스트 조치 3개 (우선순위):**
1. **이체/킬 가드 + 회귀 테스트 배포**(`fix/` 제안): 섀도 모드 1~2주 → 강제. 포함: tranId 멱등성, 커서 바닥/초기화, equity 연속성 검증, 킬 재확인(DEFER/BLOCK_REPAIR), 그리고 M17 방치 스레드 lost update 방지(상태 `state_seq` CAS 또는 방치 시 즉시 프로세스 재시작). `tests/` 에 사고 재현 테스트(`fix/test_transfer_guard.py`)를 편입. 극소액 왕복 이체로 income 지연·tranId 형식 실측.
2. **관측성**: 매 사이클(15초) 지갑잔고(equity-upnl), `totalMaintMargin/totalMarginBalance`(마진 비율 = 청산 근접도), 포지션별 마크·청산가·명목, 실행된 주문/슬리피지, API 오류율을 영속 저장하고 임계(예: 마진 비율 > 40%, dd > 25%, 킬/DEFER/BLOCK 이벤트, 연속 API 실패)에서 **사람에게 알림**(현재 저장소에 알림 채널 없음 — `momentum_rotation_loop.py` 주석). 이 데이터로 λ·킬 체결 슬리피지를 앞으로 직접 측정(R2B 의 한계 해소).
3. **전방(forward) 섀도 검증**: 현재 규칙(리사이즈 포함)을 페이퍼로 병행 기록하는 live-like 시뮬레이터를 두고 실제 equity 와 주 단위로 비교(M1 해소), 동시에 후보 캡(G42/롱레그 캡)을 *기록만* 하여 6~12개월 후 실데이터로 평가. 레버/킬 변경은 이 데이터가 쌓이기 전에는 하지 않는다. (대안 보조조치: 킬 실패 대비 독립 감시 프로세스·다른 IP 에서의 읽기 전용 경보.)
