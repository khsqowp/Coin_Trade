## Outcome-blind eligibility gate

For each of the 55 pattern-direction claims separately and each deadline (10h and 20h):

1. Count all issued signal IDs and calculate coverage over the frozen scheduled symbol-hour denominator.
2. Create a deterministic, outcome-blind non-overlapping count independently for each claim and deadline. Sort issue timestamps within each symbol, retain the earliest signal, then skip signals whose timestamp is strictly earlier than the retained signal timestamp plus the deadline; an issue exactly at expiry may be retained. This count is only an eligibility statistic and never replaces the future all-issued M2 denominator.
3. A claim is frequency-eligible only if coverage is at least 10%, its non-overlapping count is at least 200, and signals occur on at least 20 distinct eligible symbols. Report all 55×2 claims, including zero-signal and failed claims.
4. Separately report hourly-bar completeness, pattern counts per symbol, overlapping signal counts, opposing-pattern collisions, and symbols failing the data-availability gate.

If no claim passes all three signal-volume gates, stop this strategy family. Do not lower coverage or sample thresholds. If any claim passes, do not inspect outcomes yet; first submit a new preregistration covering next-executable entry, fixed target/stop distances and tie/gap rules, fees/slippage/funding, paired baselines, WFA, multiple-testing family, 1,000-order Monte Carlo, parameter-neighborhood sensitivity, and a genuinely untouched OOS boundary. Because this historical panel is already exposed development data, it cannot serve as confirmatory OOS for a selected claim; performance evaluation must use a prospectively sealed period collected after the performance preregistration. The frozen project gate remains OOS all-issued M2 ≥80%, non-overlapping N≥200 across ≥20 symbols, ≥10% coverage, positive cost-adjusted expectancy, and the other SPEC requirements.

## Post-hoc union-frequency probe (exploratory only)

The first individual-pattern frequency run found no individual claim meeting the fixed ≥10% coverage gate. After seeing that result, one deterministic union family was added for exploration: `ANY bullish` emits one long signal if one or more of the 30 bullish claims fire; `ANY bearish` emits one short signal if one or more of the 25 bearish claims fire; and `ANY two-sided` emits one signal if either direction fires, using the paper's direction-specific trend filter. Multiple same-side patterns at one symbol-hour are deduplicated. The rule is not tuned, and individual claims remain separately reported. This is a post-hoc frequency exploration, counted as one additional aggregation family; it cannot be represented as preregistered evidence or as a performance result. Any future M2 evaluation must be prospectively preregistered and sealed before outcome access.

That implementation was incorrect. Original figures are preserved above as historical execution records, not as gate decisions. A corrected scanner now uses per-symbol×UTC-hour scheduled slots for the ≥10% gate, while retaining feature-eligible coverage as a diagnostic. The new recheck supersedes all earlier eligibility labels; no outcome path has been opened.

## Source limits

Moser & Brauneis examine hourly OHLC reversal patterns through 24-hour cumulative returns and use a stepwise SPA procedure, but they do not evaluate this project's target-first barriers. Their paper explicitly leaves win/hit ratios for future research, omits transaction costs in its main return analysis, and assumes execution at the hourly close. The article is a hypothesis source only, not evidence that the Binance USDⓈ-M implementation is profitable or meets the 80% gate. The paper reports return horizons of 1, 2, 3, 6, 9, 12, 15, 18, and 24 hours; 10h and 20h in this project are a separate contract.
