## Purpose and result isolation

The first exploratory implementations exposed implementation ambiguities and defects before their performance figures were released to the orchestrator. The US first pass incorrectly reset drifted weights to target weights daily and is discarded. A later US run's half-L1 cost convention does not unambiguously match per-side fees and is not accepted as canonical. The KR first pass duplicated period turnover/cost summaries and is discarded. The next run uses the semantics below. All runs remain survivor-cohort exploratory and cannot count as valid strategy passes.

## Frozen arithmetic

1. **Cohort and K:** Use only the frozen price-cache intersections in the base registration: US 7 security lines (K=2), KR 21 security lines (K=5). Missing current members stay excluded and are listed. US GOOG/GOOGL are two security lines for equal weight, although they represent one issuer. KR cash holdings are not securities and are excluded. The KR input list is an ETF top-holdings snapshot, not all KOSPI 200 constituents.
2. **Prices and dates:** Use local adjusted `Close` for returns and close-based signals; `High` is additionally required only for the frozen Donchian 126-day breakout. The current data source describes the OHLC cache as KIS adjusted-price mode; exact per-field corporate-action behavior remains unverified. Do not fetch, fill pre-listing prices, or synthesize prices. Calculations use the market's union of observed dates. For a held security with a missing close after its first observed price, mark at its last observed close; do not generate a signal/order for that security on the missing date. Require at least 253 observed bars before an instrument can signal. Segment indicators may use any cached observations strictly before the segment start as warm-up; segment P&L itself starts with cash=1.0 on the first observed market date in that segment.
3. **Signals and fills:** All signals use information through close t. A signal generated at close t executes at the next market date's close. No same-close fill. Existing shares are first marked at the close-to-close return, then the scheduled trade executes. Trade costs are deducted at execution.
4. **Monthly rules:** At each calendar month's final observed market date, compute the full target for the eligible frozen cohort. Execute at the next market date's close. Select the top K eligible candidates; give each selected security exactly 1/K of post-cost NAV. Any unfilled slots remain cash. Names absent from the new target are fully sold at that rebalance. Between monthly executions, positions drift with price; no daily rebalancing.
5. **Donchian exits:** Monthly entries are exactly the frozen `DONCHIAN_126_63` rule. Separately, each close checks whether a held name is below the previous 63 observed closes' minimum close (current day excluded). If true, schedule its full sale for next market date close and keep that slot in cash until the next monthly entry event. A pending exit takes precedence over a same-day monthly target. Any name not selected at month-end is sold then. No same-date exit-and-reentry.
6. **Costs and turnover:** Let `delta_i` be target notional minus drifted pre-trade notional at execution. Gross buy notional is `sum(max(delta_i,0))`; gross sell notional is `sum(max(-delta_i,0))`. `total_turnover_x = sum((gross_buy+gross_sell)/pretrade_NAV)`; this counts both trade legs, not half-L1. Apply market buy fee/slippage to gross buys and market sell fee/slippage/tax to gross sells separately. To avoid negative cash from fees on fully invested target weights, solve target holdings as target weights times post-cost NAV (iterating target NAV to a 1e-10 relative tolerance, max 20 iterations); deduct fees from NAV/cash. If the iteration does not converge, mark the run failed. The KR tax is a fixed 0.18% exploratory friction assumption for all dates, not historical statutory tax accounting. The KR stress case doubles only slippage.
7. **Portfolio accounting:** Start each scored segment with NAV=1.0 cash. On each date, mark existing security values using that date's close-to-close return; execute signals from the preceding close; deduct costs; then hold the resulting shares/cash. If a security has no prior close, it cannot be held before its first observed price. Do not assume short positions, leverage, or interest on cash. For the B&H baseline, define each security's fixed gross notional as `G = segment-start NAV / (N * (1 + buy_fee_rate))`. Buy that fixed gross notional on the segment's first date when a price is available. If a frozen-cohort security has no price yet, reserve `G * (1 + buy_fee_rate)` cash for it until its first observed price, buy gross notional G then, and never rebalance/sell it afterward. This makes all initial and delayed buy costs affordable without negative cash or borrowing. This is a gradual-entry cohort baseline, not an index benchmark.
8. **IS/OOS:** Compute IS (2018-01-01 through 2022-12-30) and OOS (2023-01-01 through last cached date) as separately initialized accounts. For OOS, the portfolio starts at 2023 cash and may use cached signal features/month-end targets strictly before 2023, but no IS holdings/equity carry over. The OOS B&H comparison also starts with cash on the first OOS market date. This is a chronological split inside a future-selected survivor cohort, so it is not valid index PIT OOS evidence.
9. **Benchmark:** For each segment, the B&H baseline allocates cost-adjusted fixed equal gross notional across frozen-cohort security lines, initially buys those with a price on the first segment date, and buys any later-listed/cache-starting security from its reserved cash slot on its first observed date; weights then drift and are not rebalanced. This is a survivor-cohort security-line benchmark, not the S&P 500/KOSPI 200 index, not equal-weight by issuer (GOOGL/GOOG are separate lines), and not an ETF total-return benchmark.
10. **Metrics:** Calculate CAGR as `(final_NAV / 1.0) ** (365.25 / calendar_days_between_segment_first_and_last_observation) - 1`; maximum drawdown relative to the running peak including initial NAV=1.0; annualized Sharpe as `mean(daily_simple_returns) / population_std(daily_simple_returns, ddof=0) * sqrt(252)`, risk-free rate 0; turnover as defined above; cumulative transaction fees/tax/slippage in initial-NAV units (initial NAV=1.0); and calendar-year OOS returns from the prior year-end NAV (2023 starts at initial NAV=1.0) to that calendar year's last observed NAV. Label the final incomplete calendar year as YTD through the final cache date. Preserve every market × strategy × cost scenario and every failed/empty case.

## Decision rule

The frozen indicator rules and parameters do not change. If an implementation cannot meet these semantics, do not report its performance as the canonical screen; record the implementation failure and stop that case. Any result is `exploratory only`, regardless of whether its metrics beat the cohort benchmark.
