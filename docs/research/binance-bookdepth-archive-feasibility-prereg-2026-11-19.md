# Binance USD-M bookDepth archive feasibility audit — preregistration

Registered: 2026-11-19, before downloading or parsing any bookDepth archive payload. This is a data-source audit only, not a strategy or outcome test.

## Question

Can the historical USD-M `bookDepth` archive supply structurally complete, internally consistent, time-stamped cumulative depth features for a later 1-minute-anchor study, without treating it as raw L2 or an executable quote feed?

The Binance Vision terms describe historical order-book metrics and restrict usage to personal, non-production historical backtesting. Derived data remain governed by those terms. No live signal, execution, compensated distribution, or production use is permitted in this study. [Official terms](https://github.com/binance/binance-public-data/blob/master/TERMS_AND_CONDITIONS.md)

## Frozen parsing and diagnostics

For each ZIP, record URL, HTTP status, compressed bytes, published checksum, locally calculated SHA-256, CSV header, row count, parse failures, and symbol/date identity. The expected header is exactly `timestamp,percentage,depth,notional`; a mismatch is reported and no fallback column guessing is allowed. Timestamp strings must parse as timezone-naive ISO 8601 date-time values; parse failures fail that symbol-day and are not coerced. Interpret valid timezone-naive values as UTC only if every parsed timestamp falls within the UTC day encoded by the archive filename; otherwise mark time semantics unresolved and do not shift rows. This UTC interpretation is an explicit audit assumption because the public issue's request for timestamp/timezone clarification has no visible maintainer answer.

Binance's FAQ describes book depth as cumulative bids/asks at percentage distances from mid and states USD-M depth may be expressed in base quantity or notional. A Binance Public Data maintainer's response describes `percentage` as distance from mid and `depth`/`notional` as coin/notional terms, but the issue does not document the complete archive schema. The published 2026 defect report states 2,880 snapshots/day at nominal 30-second cadence. Treat these as source references, and verify all values from the fixed files rather than silently assuming them. [Binance Futures book-depth FAQ](https://www.binance.com/en/support/faq/detail/afd1ccded7ca41108b281c927fefa3a0), [public-data maintainer clarification](https://github.com/binance/binance-public-data/issues/447), [reported archive cadence](https://github.com/binance/binance-public-data/issues/496)

For the first fixed sample file (`BTCUSDT`, `2025-01-01`), record the observed percentage set `B`; freeze that schema template for comparisons across the remaining 99 symbol-days. Each timestamp must have exactly one row for each `b ∈ B`, no duplicate `(timestamp, percentage)` key, and the same `B` must hold in every archive. For each file, sort the 2,880 distinct timestamps and require: (a) the first timestamp lies in `[00:00:00, 00:00:30)` UTC on the filename date; (b) every one of the 2,879 consecutive timestamp differences is exactly 30 seconds; and (c) the final timestamp is therefore in `[23:59:30, 24:00:00)` UTC on that date. The first timestamp's seconds offset is allowed to vary within the first 30-second interval, but no other jitter or missing/extra timestamp is allowed. If a timestamp is timezone-naive, apply the explicitly stated UTC audit assumption; if the parsed values do not fit these rules, report actual timestamps/gaps and fail the frozen cadence gate without shifting, resampling, or repairing them. This verifies regular archive spacing under the stated UTC assumption; it does not prove the exporter timestamp's event-time semantics.

Report:

1. Null, non-finite, negative, and zero `depth` / `notional` counts; duplicate keys; and per-file symbol/date identity.
2. Per-timestamp cumulative-depth monotonicity on each sign side as `abs(percentage)` widens, using relative tolerance `1e-8` and absolute tolerance `1e-10`. If observed percentage values do not support an unambiguous ordered band set or the cumulative interpretation is contradicted, mark this diagnostic `UNRESOLVED` instead of inventing a mapping.
3. Per-day/per-band distinct-value counts of `round(notional / depth, 6)` and longest repeated-pair run for `(depth, notional)`. A non-finite value or `depth == 0` makes the ratio undefined: do not divide, impute, drop, or replace that row. Record the offending row count, fail that symbol-day's ratio diagnostic, and if any such row occurs in the 44 known-issue comparison cells, mark the overall issue `NOT EXACTLY REPRODUCED` and report the cell as `UNCOMPUTABLE` (without treating it as a matching count). For known-issue replication, calculate the ratio only when all rows in that symbol-day/band are finite and have strictly positive depth, then use exact integer equality against every cell in the issue's published SOLUSDT table for `2026-09-02` through `2026-09-06` (8 bands per day), and exact equality against the published `+0.2` counts `(SOLUSDT=4, BTCUSDT=3, ETHUSDT=2, AVAXUSDT=1)` on `2026-09-06`. The issue's table and cross-symbol values are reproduced only if all 44 counts match; otherwise report the per-cell differences and mark the issue `NOT EXACTLY REPRODUCED`. No tolerance, substitute band, date, symbol, or partial-match rule is allowed. This comparison tests reproducibility of the public report, not the truth of the report or the cause of any anomaly.
4. In the 80-day main sample, report per-band distinct `round(notional / depth, 6)` counts, most-frequent `(depth, notional)` pair occupancy, and longest repeated-pair run as descriptive source diagnostics only. There is no freeze pass/fail threshold for this sample: do not label any 2025 band frozen or defective based on an arbitrary repetition cutoff or the result of the 2026 diagnostic. Any exact issue replication is reported only for the fixed 2026 diagnostic sample and does not qualify or disqualify the 2025 sample.
5. Do not infer spread, best bid/ask, queue position, order-level replenishment, or executable fills from cumulative percent-band metrics. Do not construct signals or inspect TP/SL/M2/directional outcomes.

## Decision rules

- A checksum failure, malformed archive, symbol/date mismatch, duplicate timestamp-band key, non-2,880 timestamp day, timestamp outside the specified first/last 30-second bounds, any inter-timestamp gap other than exactly 30 seconds, or inconsistent percentage set is an integrity failure for that symbol-day.
- If cadence or band schema differs from the maintainer/issue references, report the exact actual schema and fail the frozen sample gate; do not coerce it to the expected schema.
- In the 80-day main sample, any `depth` or `notional` value that is null, non-finite, zero, or negative fails that symbol-day's value-integrity gate; no row may be dropped or repaired. In the 20-day diagnostic sample, record such values and mark the affected ratio comparison uncomputable; do not impute. Any violated cumulative-depth invariant is reported at the exact symbol/date/band level; checksum success does not override content-quality failures. Repeated-value statistics in the main sample are descriptive and cannot independently trigger a defect label.
- Overall source disposition is fixed as follows: `MAIN_STRUCTURE_PASS` only if all 80 main-sample symbol-days pass checksum, archive identity, exact CSV schema, timestamp-band uniqueness, fixed 30-second cadence, frozen band-set, and positive finite-value gates. Any failed item yields `MAIN_STRUCTURE_FAIL`. Report cumulative-depth semantics separately as `PASS`, `FAIL`, or `UNRESOLVED`; an unresolved side/band mapping prevents claiming that cumulative-depth semantics were validated, even if `MAIN_STRUCTURE_PASS`. The 20 known-issue days are diagnostic only and cannot change the 80-day main-structure disposition. Neither result authorizes a strategy outcome test; a separate novelty review and outcome preregistration remain mandatory.
- The 2025 sample can qualify only the tested archive structure and dates. It cannot prove historical completeness outside the sample or predictive utility.
- The 2026 known-issue diagnostic is descriptive only. Reproducing or failing to reproduce the report does not change the fixed strategy trial count and does not authorize outcome scoring.
- Even if the source passes, this archive is aggregated depth telemetry, not raw synchronized L2. A separate novelty review and pre-registration are required before any M2 performance test. It cannot be represented as satisfying R005's event-level replenishment rule or H3's top-five-level rule without a new explicit hypothesis.
