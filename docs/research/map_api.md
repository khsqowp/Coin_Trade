# 신규 데이터 전략 지도 (map_api): 온라인 에이전트 보고

작성 2026-10-13. 코드: app/rs_map_api_{fetch,feat,run,stats,null,final}.py. 결과: docs/research/map_api_{results,final,stats}.json.
엔진은 app/rs_final_engine.py(수정 없음)를 그대로 사용. 비용 0.10%/편도 + 실제 펀딩, 위상(phase) 평균. 기준(live) = 14일 모멘텀/3일/K8 + BTC 급락시 현금.
용어: 연수익률=CAGR, 최대 낙폭=MDD, Calmar=연수익률/최대낙폭, 위상=리밸런스 시작일 오프셋, 널(null)=무작위 신호로 같은 실험을 반복한 기준선.

## 0. 중단 사항 (규칙에 따른 즉시 중지)
- api.coingecko.com 이 9번째 호출(앞선 8호출은 성공)(초당 0.45회 이하 속도)에서 HTTP 429 를 반환 -> 규칙대로 **모든 신규 수집을 즉시 중단**했다.
  중단 표식: `.rs_cache/online/STOP`. 이 때문에 계획했던 data.binance.vision 의 metrics(미결제약정/롱숏비/테이커비) 일별 덤프 약 1.7만 건(10종목 x 2022-01~)은 **한 건도 받지 못했다**.
- 주인 확인 없이 재개하지 않음. 재개하려면 STOP 파일 삭제 후 `python -m app.rs_map_api_fetch vision` (이미 받은 건 건너뜀, 순차 1.05초 간격).
- 사전 프로브(HEAD 요청 ~15건)로 확인: metrics 는 2021-07 이후 일별 파일이 존재(200). **liquidationSnapshot 은 모든 시험 날짜/종목 404 (덤프 없음)**.

### 5-1. 가장 그럴듯한 후보: 펀딩 역방향 오버레이
- 방식: 최근 7일 평균 펀딩이 높은 종목을 숏 쪽으로 기울임(모멘텀 z + 1.0 x 펀딩 z).
- 펀딩 수취 자체의 기여는 작음: 펀딩 끄면 연 59% -> 50%. 대부분은 **가격 쪽 역추세 효과**(과열 종목 되돌림).
- 비용 민감: 편도 0.15% 에서 Calmar 3.7, 0.20% 에서 3.0 (여전히 기준 2.03 상회). 기준 자체도 0.15% 에서 1.52.
- 50/50 혼합: IS 49%/14%/Calmar 3.5 (live 39%/19%/2.03), 보류구간 11%/7%/1.53 (live 14%/9%/1.58) -> 보류구간에선 우위 없음.
- 보류구간 단독: 3개 변형 중 +7%, -25%, -14%. 펀딩 파일이 09-30 에서 끝나 마지막 9일 신호 결측(보유 유지)도 있음.
- 선택 절차 그대로(IS 최고 1개)를 보류구간에 적용: +7%/낙폭 7% vs live +14%/9% -> **우위 확인 실패**(단 표본 120일).
- 워크포워드(사전 자동 선택, M3 전체 풀): 연결 OOS 44%/낙폭 29%/Calmar 1.53 vs live 48%/19%/2.47 -> **선택 절차 자체는 live 를 못 이김**.
  패밀리 d 로 한정하면 3.29 이지만 패밀리를 결과 보고 고른 것이라 과대(사후 선택).
