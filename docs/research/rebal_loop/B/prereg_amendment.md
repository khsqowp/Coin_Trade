# 사전등록 보충 기록 (실행 전)

작성 시점: 2026-11-01, 실험 코드 실행 전.

1. 기존 `hash_pre.txt`는 prereg.md만 해시했고 최초 B 코드가 없어 코드 해시 요건을 충족하지 않았다. 이번 실행은 독립 구현 `rs_rebal_B_sim.py`를 추가하며, 실행 전에 prereg, amendment, 코드의 SHA-256을 `hash_pre.txt`에 기록한다. 결과 생성 후 prereg/report 해시는 기존 `hash_log.sh post`로 남긴다.
2. 캐시 파일의 물리적 최종행은 미래 시각(사용자 기준일 이후)을 포함할 수 있다. 데이터 종료점은 물리적 EOF가 아니라 사용자가 지정한 BTC 1h 마지막 완결 봉의 시작 시각 2026-10-09 23:00 UTC로 고정한다. 해당 봉 이후 모든 시각은 분석에서 제외한다. 시각별 결측은 보간하지 않고, 신호 계산에 필요한 336시간 가격 이력이 없는 종목은 비적격 처리한다. 포지션 보유 중 종목 봉 결측은 마지막 종가로 평가하고, 결측 구간의 가격수익과 funding은 0으로 처리한다. 해당 처리는 로컬 데이터 한계이며 캐시 원천 완전성의 증거가 아니다.
3. 시간별 독립 회계의 종료 equity는 매 시간 mark-to-market이다. 대상 리밸런스는 해당 UTC 시간 종가에서 결정하고 다음 시간봉부터 가격변동을 반영한다. Funding은 캐시 정산 시각에 해당 시간 포지션 명목으로 적용한다. 35% kill은 시간봉 종가 기준으로 감지하며 즉시 종가 청산하고 336시간 cooldown을 둔다. Crash flat은 BTC의 완결된 직전 336시간 종가 수익률이 -10% 미만인 상태에서 다음 리밸런스에 적용한다.
4. 비용 격자는 편도 수수료 5bp 고정, 편도 슬리피지 0/2/5/10bp이다. 레버리지/계정 모드는 1x alpha(deploy 100%), 4x live-like(deploy 95%), 소액계좌 현실형(4x, deploy 95%, $5 최소명목 및 prereg 가격대 수량 step)이다. IS/OOS 경계는 원문대로 유지한다.
5. 기존 일봉 `rs_final_engine` 교차검증은 의미가 있는 72h의 정렬 위상 0 기준으로만 비교한다. 엔진의 입력해상도/청산/비용 및 계정 회계 차이를 수치와 함께 보고하고 동일성 요건으로 취급하지 않는다.
6. 이 보충은 실행 전 모호성 해소다. 다른 규칙, 임계치, 표본 구간, 검정 기준을 결과를 보고 변경하지 않는다. 자원/환경 제한으로 격자 전체를 완료하지 못하면 부분 결과를 완전 격자처럼 표시하지 않고 실행 범위와 실패 원인을 보고한다.
