# 리밸런스 주기 연구 B — 최종 보고서

## 판정: **2 — 구분 불가**

72시간보다 빠른 cadence가 더 낫다는 증거가 없다. 1시간 주기는 72시간보다 유의하게 나빴고, 나머지 후보 가운데 일부의 OOS 점추정은 플러스지만 신뢰구간·Holm·고원 기준을 통과하지 못했다. 숫자 분류는 사용자 지정 1/2/3의 뜻이 주어지지 않아 `1=개선 입증`, `2=구분 불가`, `3=해로움 입증`으로 해석했다. 이번 결과에서는 cadence 전체 개선이 아니라 2번이다. P=1의 해로움은 개별 주기 결과다.

## 실행 요약

- 사전등록 경계: IS 2022-01-01 00:00 UTC–2024-06-30 23:00 UTC, OOS 2024-07-01 00:00 UTC–2026-10-09 23:00 UTC. 현지 캐시 1h 봉의 BTC 마지막 포함 시각은 요청된 2026-10-09 23:00 UTC다. 45/45 유니버스 파일이 해당 시각까지 존재했다. 물리 EOF에 더 뒤의 자료가 있어 해당 행은 사용하지 않았다.
- 전체 격자: P=1..72, `min(P,8)` 위상, 수수료 5bp 편도, 슬리피지 0/2/5/10bp 편도, 1x alpha, 4x live형, 소액계좌형. 총 864개 셀; 각 셀의 전 위상을 실행했다.
- 계산 환경: 사용자가 지정한 전용 bvenv Python, NumPy/Numba/Pandas/SciPy; `NUMBA_CACHE_DIR=B/.nbc`. 네트워크·라이브·설정·주문은 사용하지 않았다. 생성물은 B/ 안에 저장했다.
- 로컬 캐시 funding 파일의 8시간 정산 행 커버리지 평균은 97.31% (45개 심볼 파일). 누락 정산은 0으로 처리했다.
- 초기자산은 alpha/live 1 단위, 소액계좌형은 $1,000으로 설정했다. $1 규모에서는 $5 최소명목을 만족하지 않아 주문 전부가 생략되므로, 최소명목을 시험할 수 있도록 $1,000을 선택했다. 이 값은 prereg 문서에 명시되지 않은 구현 가정이며, 최초 격자 실행 직전 commentary에서 공개했으나 실행 전 amendment/hash 파일에는 추가하지 못한 프로토콜 누락이다.

## 독립 시뮬레이터와 회계 검증

새 코드 [rs_rebal_B_sim.py](rs_rebal_B_sim.py)는 UTC 1h 종가 신호, 다음 시간 봉부터 수익 반영, 과거 336h 모멘텀, 양끝 8개 포지션, 시간별 mark-to-market을 구현했다. 미완결 lookback, 정확한 시각의 바가 없는 종목은 신호에서 제외했다. 포지션 가격은 결측 시간에 마지막 가격을 사용하고 결측 수익·funding을 0으로 둔다. funding은 정산 timestamp의 포지션 명목에 적용한다. 주문 비용은 거래 명목 × (5bp 수수료 + 슬리피지 시나리오)이며, 부분청산은 청산수량 손익을 실현하고 동일방향 추가진입은 수량 가중평균 진입가를 갱신한다. 같은 방향 포지션은 목표명목 오차 15% 초과 때만 축소/증액한다.

합성 가격 손계산 assert는 최초 구현에서 누락 entry average와 잘못된 부분청산 손익/비용 적용을 드러냈다. 코드를 수정한 뒤 매수, 추가매수, mark-to-market, 부분청산, 전량청산, funding 부호, 수수료, crash 임계치, kill 임계치, cooldown 336h, lookback 인과성을 검사해 통과했다. 검증은 별도 crash/kill 경로 시계열 통합테스트가 아니라 원장 helper와 임계치 단위 assert다. 일중 고저가·유지증거금 청산은 구현하지 않고 시간봉 종가 DD 35%에서 kill한다.

프로토콜 누락: prereg가 최초 실행 코드의 해시를 요구했으나 `hash_pre.txt`에는 사전등록 문서와 최종 실행 시점의 시뮬레이터 해시를 기록했고, 분석 코드의 실행 전 해시는 기록하지 못했다. 분석 코드 작성 및 통계 실행은 격자 산출 뒤였으며, 교차검증 1차 cadence 결과는 funding 단위 오류를 발견해 폐기했다. 이 보고서의 cadence 교차검증은 정산 비율을 재구성한 재실행 결과다. 분석 코드 사전 해시 부재를 숨기지 않는다.

## 사전등록·해시 및 한계

- `prereg_amendment.md`는 EOF의 미래 행 배제, BTC 기준 종료봉, 결측 처리, 1h 시각 규칙, 비용/계정 정의를 실험 전 기록했다. `hash_pre.txt`는 prereg/amendment/시뮬레이터 해시를 포함하며, analyzer의 사전 해시는 누락됐다. `hash_post.txt`는 prereg 및 이 보고서의 사후 SHA-256이다.
- 결과는 로컬 캐시의 45개 생존종목 유니버스를 사용한다. 상장폐지 종목과 거래소 상장 시점 전 기록 부재는 생존편향을 만든다. 종료일의 완전성은 BTC 기준 사용자 지정 시각으로 제한했으며, 모든 종목 데이터 원천의 독립 완전성은 확인하지 않았다.
- 결측 봉의 보유가치는 직전 종가로 유지하고 가격수익·funding은 0 처리했다. 현물/선물 basis, 시장충격, 호가폭, 주문 거절, 거래소 step 실제 메타데이터, 시간봉 내부의 가격경로는 모델링하지 않았다. 소액 모드 step은 사전등록된 가격구간 규칙을 썼다.
- kill은 시간봉 종가 기준이며 종가 슬리피지 외 손절 체결 격차가 없다. 실전 청산/마진콜 위험은 과소평가될 수 있다. funding 누락 0 처리도 결과에 영향을 준다.
- bootstrap은 단일 OOS 경로, 원형 168h 블록, 2,000회에 의존하며 비교 주기는 서로 상관돼 있다. max-statistic 검정은 근사 reality check다. MDE가 커서 작은 개선을 검출하기 어렵다.
- 어떤 결과도 라이브 변경, 설정 수정 또는 실거래 허가를 뜻하지 않는다. 판정은 과거 데이터/모델 조건 하에서만 적용된다.
