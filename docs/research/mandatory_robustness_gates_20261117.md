# 필수 강건성 검증 게이트 — 2026-11-17

## 적용 원칙

사용자가 지정한 세 검증은 모든 신규 전략 및 결과를 보고하는 후보에 필수다. 전략의 기본 백테스트 수익률이 높더라도 세 게이트 중 하나라도 실패하면 전략을 통과·승인·실전투입 후보로 판정하지 않는다. 자료가 모자라 계산할 수 없는 경우도 통과가 아니라 `INCONCLUSIVE`다. 이 검증은 각 시장의 기존 성과목표를 대체하지 않고 추가한다.

확인된 사용자 기준은 다음과 같다.

- 국장과 미장 각각: 순비용 CAGR ≥20%, MDD ≤30%, 연환산 Sharpe ≥1.0, OOS 왕복거래 ≥200.
- 코인: 각 사전등록 claim의 all-emitted target-first M2 ≥80%; 별도 outcome-blind 비중복 표본 N≥200 및 ≥20종목. 기한 종료 방향 정확도는 별도 보고한다.
- 라이브 주문·실거래는 범위 밖이다. 연구 단계는 백테스트/모의 평가로 제한한다.

## 세 가지 필수 검증

### 1. Monte Carlo 거래 순서 재배열

- 완료 OOS 거래의 실현 순수익 결과를 고정 seed로 1,000회 무작위 재배열한다. 각 재배열에서 거래 순서 NAV와 MDD를 다시 계산하고, 관측 OOS MDD·중앙 MDD·P95 MDD·최대 MDD를 함께 보고한다.
- 포지션 위험/사이징의 강건성 판단에는 역사상 단일 최대 MDD가 아니라 P95 MDD를 사용한다. 최종 포트폴리오 허용 MDD가 미정인 경우 P95를 산출만 하고 임의의 계좌별 포지션 크기를 권고하지 않는다.
- 재배열은 시간·종목·동시보유 의존성을 보존하지 않는 스트레스 진단이다. 이 한계를 보고하고, 의존성을 보존하는 WFA/블록 또는 포트폴리오 수준 검증을 대체하지 않는다. 동시 포지션 전략에서는 포트폴리오 일자 블록도 별도로 검사한다.
- 결과를 본 뒤 seed, 재배열 단위, 비용, 거래 집합을 바꾸지 않는다. 거래가 200건 미만이면 전략의 OOS 자격부터 미달이며 재배열을 성공 근거로 사용하지 않는다.

### 2. Walk-forward

- 각 구간에서 과거 개발창만 이용해 파라미터를 고정하고, 바로 뒤의 미관측 평가창을 순서대로 채점한다. 겹치는 보유/라벨 구간을 purge하고 사전등록 embargo를 적용한다.
- 기준 프로토콜은 개발 504일 + 평가 252일, 평가 종료 후 252일씩 전진하는 5개 평가창이다. 데이터 주기에 따라 거래일(주식) 또는 달력일(코인) 단위를 사전등록 문서에서 명시하고, 결과에 맞춰 단위를 바꾸지 않는다. 각 코인 timeframe은 동일한 달력 경계에서 해당 timeframe 봉으로 계산한다.
- 5개 창 각각의 표본수와 순비용 성과, 합산 OOS 성과를 보고한다. 불완전·빈 창도 숨기지 않는다. 데이터가 전체 5개 창을 지원하지 못하면 기간을 줄이지 않고 `INCONCLUSIVE`로 판정한다.
- 개발창에서 본 성과를 OOS 성과로 합치지 않는다. 개발창별 재최적화는 사전등록된 작은 격자 안에서만 허용하고, test 창 결과는 다음 창의 선택에 쓰지 않는다.

### 3. 인접 파라미터 민감도 / plateau

- 핵심 파라미터와 중심값, 인접 격자, 각 이웃의 통과 기준을 결과를 보기 전에 고정한다. 중심점만 급등하고 이웃이 무너지면 `SPIKE`로 분류하고 탈락시킨다.
- 결과 미평가·표본 부족·수치 오류 이웃은 pass로 세지 않는다. 모든 사전등록 이웃 및 실패 셀을 기록하고, 유리한 이웃만 선택하지 않는다.
- 코인 공통 기본 gate: 네 개 이상 유효 인접 설정이 있어야 평가 가능하며, 인접 설정의 80% 이상이 사전등록 기준을 통과하고 인접 M2 중앙값이 기준 설정 대비 10%p를 초과해 하락하지 않아야 plateau로 본다. 해당 claim에 적용되는 더 엄격한 사전등록 기준이 있으면 그 기준을 우선 적용한다.
- 주식 후보는 각 시장의 개별 사전등록에서 고정한 국소 이웃 및 성과 기준을 적용한다. 기존 후보 문서의 구체적 plateau 조건을 완화하지 않는다.
- 테스트 창 성과를 보고 파라미터를 다시 조정하면 같은 OOS의 재사용이므로 해당 시험은 확인시험 자격을 잃고 새 탐색 trial로 기록한다.

## 판정·보고

각 전략 결과에는 세 게이트별 `PASS / FAIL / INCONCLUSIVE`, 입력 데이터·코드·설정 해시, trial ID, seed, 기간/창 경계, 전체 파라미터 격자, 실패 사유를 기록한다. 세 게이트와 시장별 성과 목표를 모두 충족하기 전에는 “검증된 전략”으로 표현하지 않는다. 한 게이트 실패는 개선 허가가 아니다. 사용자가 정한 최대 1회 개선 제한 및 새 trial 기록을 따른다.

이 문서는 검증 절차를 고정한 지침이다. 전략의 성과를 증명하거나 시장 데이터 시험이 완료되었다는 의미는 아니다.
