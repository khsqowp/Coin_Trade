# Preregistration: one-hour return reversal source screen

- Status: frozen before this screen's outcome is calculated. One fixed signal, two fixed horizons, no parameter grid, and no result-driven refinement.
- Motivation: Xue and Zhou (2026) report that the previous one-hour return negatively predicts subsequent one- to four-hour returns across a broad Binance USDT-pair sample. This test is a local, source-inspired replication screen, not a reproduction of their full econometric design or a claim of a tradable edge.
- Candidate: at each eligible hourly close, let `r_t = log(close_t / close_(t-1))`. If `r_t > 0`, signal SHORT; if `r_t < 0`, signal LONG; exact zero emits no signal. No magnitude filter, trend filter, or learned threshold is permitted.
- Horizons: H=1 and H=4 hourly candles. H=1 uses every eligible hourly anchor. H=4 uses only anchors whose signal-close UTC hour is divisible by four, so same-symbol H=4 test intervals do not overlap.
- Execution: signal after the just-closed bar; enter at the next hourly candle open; exit at the close of the H-th held candle. No incomplete candle is read. A signal is excluded only if the complete forward window crosses its pre-existing split boundary; missing rows are a data-gate failure, not silently skipped data.
- Outcomes: (a) source-aligned M1 direction is whether the expiry close is in the predicted direction relative to the signal close; (b) executable gross trade return is the signed next-open-to-expiry-close simple return; (c) net expectancy subtracts the fixed 10 bp base or 30 bp stress round-trip fee proxy and adds signed archived funding while held. No spread or slippage is available, so costs remain incomplete execution proxies. M2 is `NOT_MEASURED`: this source does not specify target/stop barriers, and this screen will not invent them after observing outcomes.
- Controls: same-anchor momentum (LONG after positive prior-hour return, SHORT after negative), always-LONG, always-SHORT, and flat/no-trade. Compare per-event and synchronized cross-sectional hourly means; do not treat simultaneous coins as independent observations.
- Data: fixed 36-symbol USD-M cohort from `docs/research/inventory/usdm_archive_coverage_20261120.json`, exact common archive months 2023-03 through 2026-05, using the already checksum-verified `klines_1h`, `mark_price_1h`, and funding archive. Original bytes are read-only. This history and its splits were exposed in earlier Coin_Trade studies; all outcomes are exploratory and cannot qualify as sealed OOS.
- Splits: use the existing historical split boundaries for descriptive stratification only: development `[2023-03-23 15:00, 2025-03-01 00:00) UTC`, validation `[2025-03-01 00:00, 2025-11-01 00:00) UTC`, and previously exposed evaluation `[2025-11-01 00:00, 2026-06-01 00:00) UTC`. No split is represented as untouched validation.
- Inference: report every split, each symbol, issued count, coverage, M1, gross/net mean, funding contribution, controls, and a synchronized 7-calendar-day moving-block bootstrap with 1,000 draws for market-time means. Bootstrap intervals are descriptive, not promotion evidence; the candidate family trial count is one signal rule × two preregistered horizons.
- Screening decision: only if at least one horizon has positive net mean under both base and stress costs, a positive lower 95% moving-block interval under both scenarios, and no single symbol contributes more than 25% of total positive gross PnL may the idea proceed to a separately preregistered M2 rule-design study. Otherwise REJECT this source-inspired setup. Passing this screen is not a core pass: final requirements remain M2 target-first >=80%, total and separate non-overlap N >=200, >=20 symbols, >=10% coverage, positive net expectancy under both costs, Wilson lower bound above the frozen valid baseline, and a genuinely untouched forward period.
- Causality tests: signal sides must be invariant to truncation at the forecast anchor and to arbitrary mutations strictly after that anchor. Synthetic tests cover exact-zero returns, horizon boundaries, entry/exit indexing, and funding interval inclusivity.
- Reproduction: persist the preregistration SHA-256, code SHA-256, source manifest SHA-256, exact command, signal ledger, per-symbol and per-split outputs, and status in a new immutable run directory. No existing run, database, or registry row is rewritten.
