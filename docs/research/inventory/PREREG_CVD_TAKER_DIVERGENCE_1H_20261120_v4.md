- All test claims in v3 clauses 10 and 11 form one family of exactly 10 one-sided tests: 8 treatment-vs-direction-baseline tests (four baselines × two horizons) and 2 CVD-vs-price-only tests (two horizons). ## Exact synchronized moving-block bootstrap

1. **Fixed calendar grid.** Construct one UTC date grid from `2023-03-23` through `2025-02-28`, inclusive. For each date, include only anchors whose entire 20-hour path completes strictly before `2025-03-01T00:00:00Z`; late-day anchors that cannot meet that boundary are excluded before signal/outcome scoring. Include all calendar dates, including dates with zero eligible signals in either arm. Do not shrink the grid based on observed signal counts.
2. **Daily rows.** For each date and each of the CVD and price-only arms, store the number of issued eligible events and their M2 hit/miss labels for the 10h and 20h horizons. Invalid, gap, timeout and abstaining events remain misses per v3. A no-signal date has count zero and contributes no synthetic event.
3. **Observed statistic.** For horizon h, compute event-weighted `M2_CVD(h) - M2_price_only(h)` using all eligible events on the fixed grid. Both arms must have at least one eligible event; otherwise the test is NOT EVALUABLE.
4. **Block sampling.** Let `K` be the fixed grid length. For each replicate, independently draw block start indices uniformly with replacement from integer range `[0, K-7]`. Append each contiguous seven-date block without wraparound until at least K dates have been appended; truncate the concatenated sequence to exactly K dates. Use the same sampled date-index sequence for both arms and both horizons in a replicate. This preserves paired calendar dates and within-block dependence. It does not circularly wrap the end of the grid.
5. **Randomness.** Use NumPy `Generator(PCG64(20261120))`; generate exactly 1,000 replicates in increasing replicate index. Do not redraw invalid replicates. A replicate is invalid only if either arm has zero total events; if more than 10 of 1,000 replicates are invalid, mark both-horizon bootstrap inference NOT EVALUABLE. Otherwise retain invalid replicates as undefined, use the valid replicates for interval and p-value, and disclose their count.
6. **Replicate statistic and inference.** In each valid replicate, concatenate the sampled daily event labels and compute event-weighted M2 difference, not the unweighted mean of daily rates. Report the 2.5th and 97.5th empirical quantiles using NumPy `quantile(method="linear")`. The one-sided raw p-value for improvement is `(1 + count(delta_rep <= 0)) / (1 + valid_replicates)`. Apply the joint 10-test Holm correction above. Incremental improvement at a horizon is supported only if its joint-Holm adjusted p-value is `<0.05` and its replicate 2.5th percentile is `>0`; both horizons must satisfy this to claim a general CVD increment. Otherwise report no confirmed increment.

## Claim criteria and implementation fingerprints

- For each horizon, treatment-vs-baseline claims are paired on all fixed CVD-treatment anchors. Abstention, invalid entry, path gap, or non-target-first result is a miss. A horizon can advance only if candidate M2 meets the frozen absolute threshold, its 95% Wilson lower bound exceeds the strongest baseline point estimate at coverage no lower than candidate coverage, and every eligible baseline comparison required to establish that superiority passes the joint-Holm threshold. The zero-coverage flat baseline remains N/A and is not tested.
- Each test implementation must record Python, NumPy, and SciPy versions; source commit; SHA-256 of v2/v3/v4 preregistrations; input-manifest hash; exact eligible-date grid; PRNG identifier/seed; and raw and adjusted p-values. Unit tests must assert deterministic replicate indices, no wraparound, exact K-length truncation, paired arm resampling, event-weighted M2, Holm adjustment, and the invalid-replicate rule before any real outcome run.
- The bootstrap does not repair historical data exposure, universe survivorship, or source publication-latency risks. Results remain exploratory and cannot count as OOS, core pass, deployment, or Phase 9 authorization.
