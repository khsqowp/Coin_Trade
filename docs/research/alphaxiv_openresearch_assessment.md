# alphaXiv/OpenResearch 조사 — 암호화폐 차트 알림·국장·미장 주식 백테스트 파이프라인 적용 가능성 평가

**조사 방법**: `https://github.com/alphaXiv/OpenResearch`를 `/private/tmp/.../scratchpad/openresearch_investigation/repo`에 읽기 전용으로 클론(depth=50)하고, README(6개 언어본 중 영문), `LICENSE`, `CLAUDE.md`, `AGENTS.md`, `SKILL.md`, `arc/experiments.md`, `agent-skills/orx-lit-review/SKILL.md`, 소스 트리(`src/`, `crates/`), 커밋 로그를 직접 읽었다. Coin_Trade 코드베이스에는 설치·실행하지 않았고, 클론·독서만 수행했다(SPEC.md 5장 규칙 준수).

## 1. 이 저장소는 실제로 무엇인가

**OpenResearch(CLI 이름 `orx`)는 "로컬 우선 ML 연구 에이전트 하니스/워크스페이스"다. 트레이딩 백테스트 도구가 아니다.**

- `CITATION.cff` 공식 설명: "코딩 에이전트(Claude Code, Codex, OpenCode, Cursor, Google Antigravity, 로컬 모델)를 문헌을 검토하고 가설을 세우고 추적 가능한 실험을 로컬/원격 컴퓨트에서 돌리고 연구 산출물을 만드는 연구 에이전트로 바꾼다."
- 핵심 개념은 **실험 트리(experiment tree)**: 루트 = 베이스라인(시작 코드 + 고정된 실행 커맨드), 모든 하위 노드는 `orx/<slug>` git 브랜치로 분기하며 "같은 커맨드, 다른 코드"만 바꾼다. 결과(지표)는 로컬 SQLite(`src/store.rs`)에 기록되고, 로그·Trackio 지표·그림·리포트는 로컬 아티팩트 폴더에 저장된다.
- 컴퓨트 백엔드는 로컬, SSH, Slurm, Kubernetes, Ray, Modal, Hugging Face Jobs, Vercel, 그리고 자체 유료 "OpenResearch box"(openresearch.sh에서 시간 단위 과금)까지 지원한다 — 즉 GPU 학습 작업을 여러 환경에 분산 실행·복구·과금 관리하는 것이 설계의 절반을 차지한다.
- 문헌 검색은 `orx discover {keyword,embedding,openalex,biorxiv,pubmed}`로 alphaXiv(arXiv 오버레이, ML/AI 중심), OpenAlex(범학문 서지 그래프), bioRxiv, PubMed(생명과학) 네 커넥터에 연결된다. 로그인 없이 동작.
- 온보딩 데모(`demo/nanochat`)는 신경망 학습 실험(nanoGPT 계열)이다 — 이 프로젝트가 가정하는 "실험"의 전형은 **모델 학습·평가 run**이며, 금융 시계열 백테스트가 아니다.
- 데스크톱 앱(macOS/Windows beta/Linux) 또는 `curl | sh` 설치형 CLI로 배포되며, 계정 생성은 "매니지드 컴퓨트"와 이메일 업데이트용으로만 필요하고 로컬 문헌 검색·실험 추적 자체는 계정 없이 동작한다.

## 2. 라이선스·유지보수 상태

- **라이선스**: `LICENSE` 파일 확인 — **MIT**(Copyright 2026 alphaXiv). 코드 재사용·포팅에 법적 장애는 없다.
- **활동성**: 클론 시점(2026-11-15) 기준 최근 커밋이 2026-11-13~14에 몰려 있고, 하루에도 수십 건씩 커밋되는 매우 활발한 개발 중인 저장소다. README에 "GitHub Trending #1 Repository of the Day" 배지가 붙어 있다 — 최근 급부상한, 하이프성이 강한 신생 프로젝트로 보인다. 버전은 `Cargo.toml` 기준 `0.2.27`로 아직 0.x 단계다.
- **메인테이너**: alphaXiv(arXiv 논문 오버레이 서비스를 운영하는 조직)가 공식 메인테이너. 조사 범위(최근 50커밋) 내 활동 계정은 5명 정도로 소규모 코어팀이며, 그중 다수 커밋이 `clo ver`/`clover`라는 자동화성 계정 이름으로 찍혀 있어 봇/자동 머지 파이프라인일 가능성이 있다.
- **구조적 위험**: 핵심 CLI/앱은 MIT로 오픈소스지만, "매니지드 컴�트 렌탈"·계정·과금·텔레메트리 수집 백엔드(`openresearch.sh`)는 저장소에 포함되지 않은 클로즈드 SaaS다. README는 "옵트아웃 가능한 익명 사용 통계와 에이전트 피드백을 기본으로 전송한다"고 명시한다(코드·프롬프트·경로·토큰은 수집하지 않는다고 주장하지만, 이는 검증되지 않은 자체 claim이다).

## 3. 두 서비스에 대한 구체적 적용 가능성 평가

### 3-1. 암호화폐 차트 진입 알림(`chart_predictor/`, P1~P5 라운드)

**적용 근거를 찾지 못했다.** P4/P5 라운드의 결론(표준 지표든, 트레이딩뷰식 규칙 기반 셋업이든 수수료를 이기는 엣지가 없음, `rounds.md` 기록)은 "가설이 부족해서" 막힌 것이 아니라 "이미 광범위하게 테스트한 가설들이 통계적으로 기각된" 상태다. OpenResearch가 제공하는 것은 (a) ML 학습 실험을 여러 컴퓨트에 분산 실행·복구하는 엔진, (b) 논문 검색 커넥터, (c) git 브랜치 기반 실험 트리 추적이다. 이 중:
- (a) 분산 컴퓨트 오케스트레이션은 이 백테스트(로컬 OHLCV, 단일 머신 CPU 연산)에 전혀 불필요한 과잉 설계다.
- (b) 논문 검색은 alphaXiv(ML/AI arXiv 오버레이)·bioRxiv·PubMed(생명과학) 중심이라 트레이딩 전략 문헌(주로 SSRN, NBER, 저널 오브 파이낸스 계열)과 도메인이 어긋난다. OpenAlex는 범학문이라 원론적으로 금융 논문도 걸리지만, 이는 이미 `development-workflow.md`가 요구하는 Exa/웹 검색으로도 동일하게 할 수 있는 일이라 이 도구를 설치해서 얻는 추가 가치가 없다.
- (c) 실험 트리(브랜치당 1개 가설, 고정 실행 커맨드, 부모 결과 동결)는 방법론적으로는 Coin_Trade가 이미 하고 있는 라운드제 백테스트(P1→P5, git 커밋별 기록, `rounds.md`)와 사실상 같은 원칙을 재구현한 것에 불과하다. 새 구조적 이득이 없다.

**결론: 의미 있는 개선 경로를 찾지 못했다.** 사용자가 이미 "의미없다"고 판단한 크립토 차트 전략 라인에 이 도구를 끼워 넣어도 null 결과가 바뀔 이유가 없다.

### 3-2. 국장·미장 주식 자율매매 연구(`docs/kr-us-equity-trader/`, 현재 E2)

**부분적으로 그럴듯해 보이지만 실제로는 약하다.** 이 파이프라인은 지금 "0.5 rule 변동성 브레이크아웃이 매수·보유 대비 엣지 없음"(`vol_breakout_0.5_rule_report.md`)이라는 결과를 막 냈고, SPEC.md는 E2 단계에서 탐색적 백테스트만 허용한다(실거래·페이퍼트레이딩 불허).

- **문헌 기반 가설 발굴**: 이론적으로는 `orx discover openalex "volatility breakout" --prioritize recency` 같은 쿼리로 모멘텀·평균회귀·변동성 전략 관련 학술 문헌을 찾아 새 가설 후보를 만들 수는 있다. 하지만 이 기능은 이 저장소 전체를 설치하지 않아도 이미 `development-workflow.md`의 0단계(GitHub 코드 검색 → 라이브러리 문서 → Exa 웹 검색)가 요구하는 작업과 동일한 결과를 낸다. alphaXiv/OpenAlex 커넥터가 주는 차별점은 "조금 더 편리한 CLI 래퍼" 정도이며, 실제로 부족했던 것(지금까지의 결과는 새로운 전략 아이디어 부족이 아니라 테스트한 아이디어들의 실증적 실패)을 해결해주지 않는다.
- **실험 추적 구조**: SQLite 기반 run 기록·git 브랜치 실험 트리는 현재 markdown 리포트(라운드별 `.md`, `strategy_research_round4_20261115.md` 등)보다 더 질의 가능한 형태이긴 하다. 하지만 이를 도입하려면 Rust 데스크톱 앱 + 로컬 서버(`orx up`, 127.0.0.1 바인딩) + SQLite 스토어 + 에이전트 하니스 통합이라는 상당한 운영 부담을 새로 들여야 한다. 지금 리서치는 1인 로컬 Python 백테스트 스크립트 수준이라, 이 무게의 도구를 들여올 명분이 부족하다. 더 단순하게 기존 git 커밋 + markdown 리포트 체계를 유지하거나, 필요하면 가벼운 run-log 포맷(JSON/CSV)만 추가하는 것이 비용 대비 합리적이다.
- **컴퓨트 백엔드(SSH/Slurm/K8s/클라우드 과금)**: 이 백테스트는 92개 종목 수준의 로컬 CPU 연산이라 전혀 해당되지 않는다.

**결론: 명목상 관련 있어 보이는 기능(문헌 검색)이 하나 있지만, 이미 요구되는 리서치 절차와 중복되고 실제로 막혀 있는 지점(전략의 실증적 엣지 부재)을 해결하지 못한다. 솔직히 말해 "도입할 만한 개선 경로를 찾지 못했다"가 정직한 결론이다.**

## 4. SPEC.md 5장 규칙에 따른 라이선스·유지보수 위험 플래그

SPEC.md: "외부 GitHub 저장소를 설치·실행하기 전에 라이선스와 코드 경로를 점검한다. README의 성능 주장은 실증 근거로 취급하지 않는다."

- **라이선스**: MIT로 호환성 문제 없음 (CRITICAL/HIGH 아님).
- **README 성능 주장 관련**: 이 저장소는 트레이딩 성능 주장을 하지 않는다("가속화한다", "연구를 돕는다" 수준의 마케팅 문구는 있음 — 이는 검증되지 않은 주장으로 그대로 받아들이지 않았다).
- **유지보수 위험(MEDIUM)**: 0.x 버전, 최근 급부상한 트렌딩 저장소, 하루 수십 커밋의 빠른 변경 속도 — CLI/스토리지 포맷이 안정화되지 않았을 가능성이 높다. 지금 당장 쓸 계획이 없으므로 당장 문제는 아니지만, 향후 재검토 시에도 "아직 0.x, 변경 잦음"을 다시 확인해야 한다.
- **운영 위험(MEDIUM)**: 기본값이 옵트아웃 텔레메트리 전송(익명 설치 ID 기준 사용 통계 + "에이전트 피드백" 전송)이다. 코드·프롬프트는 수집하지 않는다고 주장하나 이는 자체 README의 미검증 claim이며, 독립적으로 확인하지 않았다.
- **아키텍처 위험(LOW~MEDIUM, 가정 시)**: 로컬 서버(`orx up`)가 127.0.0.1에 바인딩되고 Host/Origin 검증을 한다고 문서화되어 있어 기본 로컬 사용은 상대적으로 안전해 보이나, SSH 원격 호스트·클라우드 렌탈(OpenResearch box) 기능을 켜면 자격 증명·네트워크 노출 표면이 커진다 — 이 프로젝트에서는 애초에 그 기능을 쓸 이유가 없다.

## 5. 총평

OpenResearch는 ML 모델 학습·평가를 수행하는 연구자를 위한, 문헌 검색 + git 기반 실험 추적 + 멀티 컴퓨트 오케스트레이션 도구다. 금융 시계열 백테스트나 트레이딩 전략 리서치를 위해 설계된 것이 아니며, 지금 두 서비스(크립토 차트 알림, 국장·미장 주식 백테스트)가 실제로 막혀 있는 지점—**테스트한 가설들의 실증적 엣지 부재**—을 해결해주는 기능이 없다. 유일하게 표면적으로 관련 있는 문헌 검색 기능도 이미 수행 중인 리서치 절차(Exa/GitHub 검색)와 중복되고, 이를 쓰기 위해 들여야 하는 운영 비용(데스크톱 앱, 로컬 서버, SQLite 스토어, 텔레메트리, 0.x 버전 불안정성)이 그 이득을 상회한다.

**권고**: 현재 두 서비스 어느 쪽에도 도입하지 않는다. P4/P5·vol breakout 라운드와 동일하게, 이번에도 "의미 있는 개선 경로를 찾지 못했다"는 null 결론을 그대로 기록한다.
