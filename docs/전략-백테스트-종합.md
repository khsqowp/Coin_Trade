## 1. 버그 수정 내역

### 1-1. `data.py` / `futures_data.py` — 날짜 파싱 (치명적)
`exchange.parse8601("2020-01-01")` 은 시간이 없으면 `None`. → `since=None` 으로 ccxt 호출 →
거래소가 **최근 1000봉(일봉 ≈ 2.7년)** 만 반환. `"...T00:00:00Z"` 형식을 쓴 호출부(squeeze, pullback,
TRX, 선물 프로브들)는 무사. **`crypto_mach7` + 신규 lab/sweep/portfolio 는 전부 2023-12~2026-09
데이터로만 돌아가고 있었다.** `_parse_ts` 로 날짜만 오면 `T00:00:00Z` 붙여 재파싱.

### 1-2. `mach7_indicators.add_mach7_ma_pullback` — 미래참조 3건
1. `_williams_bullish_fractal`: 봉 `i` 를 `i+1,i+2` 로 판정 → `i` 에 기록 (미래참조)
2. `FRACTAL_LOW = fractal_lows.bfill()` : 미래 프랙탈 저점으로 채움 → 손절가 > 진입가 → `risk<0` → 즉시 손실청산 (**국장 -90% 의 직접 원인**)
3. `ENTRY = 정배열 & (Close > FRACTAL_LOW)` : 상승추세면 매 봉 참, 실제 '눌림' 미감지 → 종목당 267매매

수정: 정배열 + 최근 N봉 EMA_fast 이하 눌림 + 반등확인봉(종가>전봉고가), 스윙저점 손절(진입가보다 낮을 때만), 청산 후 쿨다운 3봉, 봉내 고저로 손절/익절 판정.

### 18-2. 쏠림완화 시도 결과

- 방법은 동일 종목 누적 완료 거래 비율 상한 1개, X=10/15/20% 3단계로 제한했다. §12 cap5%/신엔진의 신호·랭킹·보유·수수료를 재사용했다. 상한 차단은 랭킹/슬롯 선정 전에 적용하여 허용 종목이 기존 순위대로 슬롯을 채운다.
- 전체 완료 거래가 0건이면 허용한다. 이후 해당 종목 완료수>상한×전체 완료수일 때 신규 진입만 차단하고, 비율이 상한 이하이면 허용한다. 미청산 포지션·당일 이후 종가 청산·미래 거래를 세지 않는다. 기존 보유는 정상 청산한다. 상한은 신규 진입 규칙이며 최종 거래 비중의 엄격한 상한은 아니다.
